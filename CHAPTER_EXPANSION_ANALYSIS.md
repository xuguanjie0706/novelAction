# Chapter Expansion System ("按卷懒展开章纲") - Complete Analysis

## Overview
The chapter expansion system is a lazy-loading workflow that converts volume-level outlines (generated by Bootstrap) into chapter-level plans (chapter_plan nodes). Users can expand any volume at any time without regenerating the entire outline.

**Key Design Philosophy**: Chapter plans are NOT event lists, but **cause-chain blueprints**: protagonist_want → obstacle → choice → cost → next_chapter_hook.

---

## 1. Main Entry Point & Route Handler

**File**: `/sessions/vigilant-gracious-ride/mnt/novelAction/apps/backend/app/routers/outline/routes_vol_expand.py`

### Route
```
POST /outline/volumes/{volume_node_id}/expand-chapters
```

### Request Body (VolExpandRequest)
```python
{
  "model_profile": str,           # "local" / "gemini" / llm_provider_id
  "llm_provider_id": str | None,  # Optional provider UUID
  "force": bool,                  # Force regenerate (delete old chapters first)
  "written_context_limit": int,   # Max prior chapter summaries to inject (default 15)
  "memory_limit": int,            # Max memory chunks (default 10)
  "promise_limit": int,           # Max unfulfilled reader promises (default 8)
}
```

### Flow
1. **Validation**: Project exists, volume_node exists, node_type == "volume"
2. **Idempotency check**: If chapter_plan children exist and force=False → HTTP 409
3. **Force mode**: Delete existing chapter_plan nodes and regenerate
4. **Context Assembly**: Call `build_vol_expand_ctx()` to gather editorial-level context
5. **Dynamic Context Queries**: 
   - `_get_written_summaries()` - Recent completed chapter core events
   - `_get_memory_chunks()` - Recent memory chunks (priority: foreshadow > character_state > conflict > event)
   - `_get_open_promises()` - Unfulfilled reader promises by priority
6. **Generation**: Call `gen_vol_chapter_plans()` with all context
7. **Linter Gate (GEN-02)**: Validate chapters, block if critical issues found
8. **Persist**: Write chapters to DB, mark volume with linter status
9. **SSE Events**: `step_start` → `context_ready` → `step_done` / `error` → `end`

## 2. Core Generation Service

**File**: `/sessions/vigilant-gracious-ride/mnt/novelAction/apps/backend/app/services/bootstrap/steps/vol_chapter_plans.py`

### Function Signature
```python
async def gen_vol_chapter_plans(
    svc: Any,  # Bootstrap service with _call_with_retry + db
    project: Project,
    volume_node: OutlineNode,
    ctx: dict,  # Editorial context from build_vol_expand_ctx
    written_summaries: list[str] | None = None,
    open_promises: list[dict] | None = None,
    memory_chunks: list[str] | None = None,
    editorial_prompt_block: str = "",
) -> list[OutlineNode]
```

### Key Features

#### A. Batching Strategy
- **30-chapter volumes**: 1 batch (chapters 1-30)
- **60-chapter volumes**: 2 batches (chapters 1-30, then 31-60)
- Batches are generated sequentially; second batch receives full context of first batch chapters to ensure continuity

#### B. System Prompt
```
你是有30年网络小说从业经验的总编辑，深度参与过数百部上百万字长篇网文的策划。
你的职责：为本卷生成章级大纲，每一章都必须是可以直接开写的创作蓝图...
[强制编辑铁律 12 条]
```

#### C. Multi-Tier Context Injection

**Tier 1 (不变量 - Invariants)**:
- 立项定位 (Project positioning: target_audience, tropes, face_slap_pattern, emotional_arc, pace_type)
- 境界体系 (Power system: all ranks/breakthroughs)
- 世界观 (World settings: max 6 key settings)
- 流派指导 (Genre kit: xuanhuan vocabulary guardrail)

**Tier 2 (卡司状态 - Cast State)**:
- 主角心理档案 (Protagonist psychology: realm trajectory, wounds, desires, secrets)
- 人物阵容 (Character snapshot: names, tiers, current realms, status)
- 关系张力台账 (Relationship dynamics)

**Tier 3-5 (故事现状、时序、节奏 - Story State)**:
- 故事线进度 (Storyline weave: which lines are active in this volume)
- 伏笔台账 (Foreshadow ledger: what seeds to plant/heat/resolve)
- 读者承诺欠账 (Reader promises: unfulfilled commitments by chapter window)
- 反派独立时间线 (Villain timeline: BOSS realm, independent actions)
- 节奏统计 (Pacing stats: face_slap density, emotional beat frequency)

#### D. Dynamic Context Blocks
```
已写章节摘要（最近 N 章，按时序——本卷必须从此处自然接续）
  1. [chapter 1 core event]
  2. [chapter 2 core event]
  ⚠️ 本卷第1章的 opening_hook 必须能直接承接上面最后1条摘要的结局状态。

关键记忆条目（世界状态锚点，生成时不得与之矛盾）
  • [memory chunk 1]
  • [memory chunk 2]
```

#### E. Volume-Level Continuity Anchors
- **上卷末悬念钩子 (prev_vol_hook_block)**: 
  - For volume 0's first batch: inject previous volume's hook
  - First chapter MUST make reader feel the hook still fermenting in first 500 words
  - choice_cost MUST include direct aftermath of previous volume's final event
  
- **批次延续锚 (prev_summary)**:
  - For second batch: pass full outline of chapters 1-30
  - Ensures chapter 31 naturally continues from chapter 30, not just last 4 chapters

#### F. Phase-Based Pacing Guidance
```
【本批节奏约束（按章节区间——必须严格执行）】
- 第1-5章（opening）: 快节奏，打脸密度 80%
- 第6-15章（rising）: 中速，建立主线对手/法宝
- ...
```

#### G. Chapter Plan Output Structure (JSON Array)

**Each chapter_plan node contains**:

Core Narrative Anatomy (4-tuple - the engine):
```json
{
  "chapter_number": 1,
  "title": "第1章：标题（≤12字）",
  "protagonist_want": "主角这章主动想要什么（必须主动，不被动）",
  "protagonist_obstacle": "具体阻力（内部恐惧 OR 外部冲突）",
  "protagonist_choice": "关键抉择（暴露性格）",
  "choice_cost": "代价（CRITICAL：不能空，不能零成本；喂给下章）"
}
```

Structure Skeleton:
```json
{
  "opening_hook": "前500字核心手段（≤30字，必须无法放下）",
  "core_event": "核心事件（protagonist_choice 的直接后果）",
  "character_change": "谁的认知/处境/关系变了（不能只外部变）",
  "end_hook": "章末钩子（具体手法，禁止「悬念丛生」套话）"
}
```

Foreshadow & Promise Management:
```json
{
  "foreshadow": "埋[伏笔|主题:xxx] / 收[伏笔代号] / 加热[代号+手法]",
  "promise_fulfilled": "兑现的承诺原文片段（否则空字符串，禁用「无」）"
}
```

Antagonist & Supporting:
```json
{
  "villain_action": "反派这章的独立行动（即便不在主视角）",
  "supporting_spotlight": "哪个配角推进了独立情节（名字+动作）"
}
```

Pacing & Emotion:
```json
{
  "reader_emotion_target": "exciting/tense/sad/romantic/mysterious/warm/anxious/epic",
  "emotional_tone": "exciting/tense/sad/romantic/mysterious/funny/epic/calm",
  "pacing": "fast/normal/slow/climax",
  "has_face_slap": false,
  "has_emotional_beat": false,
  "involved_characters": ["char1", "char2"],
  "storyline_refs": ["storyline1", "storyline2"],
  "storyline_beat_ref": "main_storyline",
  "power_milestone": "技能习得 / 境界突破 / 法宝获得（否则空）",
  "expected_words": 2200
}
```

#### H. Critical Editing Laws (12条)
1. protagonist_want MUST be active (主动欲望 not 被动应付)
2. choice_cost CANNOT be empty - this is TOP priority
3. SEQ constraint: Chapter N+1's opening_hook MUST reference chapter N's choice_cost
4. end_hook MUST be specific technique, not vague
5. villain_action CANNOT be empty
6. core_event (summary) MUST be direct consequence of protagonist_choice
7. storyline_refs MUST cross-appear (main line can't dominate >3 consecutive chapters except climax)
8. At least 2 foreshadow threads spanning volume: plant → heat → payoff
9. promise_fulfilled: if this chapter resolves a promise, cite the promise text; else empty string
10. has_face_slap frequency MUST match positioning.face_slap_pattern
11. If phase=dark_hour: ≥40% chapters have has_emotional_beat=true, pacing can't be fast 3x consecutive
12. xuanhuan: NO modern STEM/business jargon (市场调研, 逆向工程) - use 世界观内 language

#### I. Batch Error Handling
- **GEN-01 (Batch count drift)**: AI returns wrong number of chapters
  - Attempt 1: Log warning, retry
  - Attempt 2: Truncate to expected count
  - If completely empty: mark batch as failed, continue to next batch
  
- **GEN-02 (Linter blocking)**: Critical chapters fail validation
  - See "Linter Gate" section below

#### J. Token Budget
Default: 32,768 tokens
- Configurable via `VOL_EXPAND_CHAPTERS_MAX_TOKENS` env var
- For 60-chapter volumes: ~8,000-16,000 per batch

## 4. Linter Gate (GEN-02: Quality Control)

**File**: `/sessions/vigilant-gracious-ride/mnt/novelAction/apps/backend/app/services/outline_linter/gate.py`

### BLOCKING_RULE_IDS
```python
{
  "CH-04",   # choice_cost empty or placeholder only
  "CH-08",   # core_event empty (summary is empty)
  "SEQ-07",  # Chapter N+1 doesn't reference chapter N's cost
  "CM-03",   # Mystery revealed too early
}
```

### Flow (finalize_volume_chapter_commit)
1. Run `run_volume_linter()` on all generated chapters
2. Add semantic duplicate check
3. If blocking issues exist:
   - Flag all chapters with `linter_hold=True`
   - Mark volume with `extra.linter_blocked=True`
   - Store `linter_block_reason` and `linter_user_message` in volume.extra
   - **DO NOT commit to DB** - chapters remain as drafts
   - Log with severity ERROR (GEN-02)
   - Return chapters anyway (for preview/repair)
4. If pass:
   - Remove any `linter_hold` flags
   - Commit to DB
   - Persist linter report in volume.extra

### Chapter Rules (rules_chapter.py)

| Rule | Severity | Issue | Suggestion |
|------|----------|-------|-----------|
| CH-01 | high | protagonist_want < 8 chars | Supplement active goal |
| CH-02 | high | protagonist_obstacle < 8 chars | Add concrete barrier |
| CH-03 | high | protagonist_choice < 8 chars | Add decision that reveals character |
| CH-04 | **critical** | choice_cost empty/placeholder | Add consequence for next chapter |
| CH-05 | high | opening_hook < 10 chars | Add opening grab technique |
| CH-06 | high | end_hook < 12 chars | Add chapter-end cliff-hanger |
| CH-07 | medium | end_hook too vague ("悬念丛生") | Use specific technique |
| CH-08 | **critical** | core_event empty | Add chapter core plot event |
| CH-09 | high | villain_action empty/placeholder | Add independent antagonist action |
| CH-10 | medium | No involved_character_ids | Associate ≥1 character |
| CH-11 | medium | No storyline_ids | Advance ≥1 story thread |

**Design Philosophy**: Only "structural hard errors" block commit (empty fields, batch failures). Content quality issues (repetition, pacing misalignment) are warnings, not blocks.

## 7. Key Gaps & Weak Points

### A. Batch Continuity Risk
- **Issue**: If batch 1 (ch 1-30) is generated, then user edits volume settings and regenerates batch 2 (ch 31-60) the next day, batch 2 might reference outdated information from batch 1.
- **Current Mitigation**: `prev_summary` block passes full ch 1-30 outline to batch 2, but if ch 1-30 have been manually edited after generation, this context becomes stale.
- **Recommendation**: Add `last_regenerated_at` timestamp to volume.extra; warn user if >7 days since batch 1 generation.

### B. Memory Chunk Prioritization
- **Current**: foreshadow > character_state > conflict > event
- **Gap**: No weighting by recency within type. Very old character_state might be less relevant than recent event.
- **Recommendation**: Secondary sort by `created_at DESC` within each type.

### C. Linter Blocking on Valid Chapters
- **Issue**: A single chapter with CH-04 (empty choice_cost) blocks entire volume from persisting
- **Current Design**: Intentional - blocks until manually repaired
- **Gap**: No auto-repair suggestions; no partial commit (save valid chapters, flag bad ones)
- **Recommendation**: Add `auto_fixable` flag; implement repair workflow

### D. Semantic Duplicate Detection
- **Current**: Only checks for exact phrase repetition within volume
- **Gap**: Doesn't catch "same event, different phrasing" across volumes
- **Recommendation**: Use embedding similarity (existing RAG infrastructure) to detect cross-volume semantic duplication

### E. Hero's Journey Phase Alignment
- **Current**: `get_chapter_phase_guidance()` returns pacing rules per chapter range
- **Gap**: No validation that volume.phase matches expected phase at this point in series
- **Example**: If series has 5 volumes, vol 3 should be "turning" but is marked "rising" → misleads AI
- **Recommendation**: Auto-infer phase from `volume.sort_order / total_volume_count`

### F. Multi-Provider Fallback Missing
- **Current**: If model_profile API fails (auth error, blocked content), entire expansion fails
- **Gap**: No automatic fallback to alternate provider
- **Recommendation**: Try 3 times on same provider; if exhausted, try next provider in config

### G. No User-Facing Repair Workflow
- **Current**: Chapter plans can be blocked by linter; no UI to fix and re-validate
- **Gap**: User must manually edit chapter nodes in tree view, then re-run linter
- **Recommendation**: Add "Repair Suggestions" panel with inline edits, re-lint in place

### H. Foreshadow Sync Incomplete
- **Current**: `sync_chapter_foreshadow()` called during generation, but only writes `foreshadow` field
- **Gap**: Doesn't auto-create Foreshadow records in DB; only stores metadata
- **Recommendation**: Parse `foreshadow` field and create/link Foreshadow entries

### I. Word Budget Enforcement Weak
- **Current**: `expected_words` calculated per chapter, but no enforcement during draft
- **Gap**: AI can ignore and write 4000 words for a 2200-target chapter
- **Recommendation**: Inject hard constraint in draft prompt; clip output if excess

### J. Promise Fulfillment Timing
- **Current**: `promise_fulfilled` field filled during chapter plan, but actual debt collection happens during draft debrief
- **Gap**: Chapter plan says it will fulfill promise, but draft debrief might not extract it correctly
- **Recommendation**: Add inline prompt during draft asking AI to cite which promise it fulfilled

## 9. Example: Full E2E Flow for Vol 2, 30 chapters

1. **User clicks "展开章纲" on Vol 2 (volume_node_id = UUID-123)**

2. **Frontend**: POST `/outline/volumes/UUID-123/expand-chapters`
   ```json
   { "model_profile": "gemini", "force": false, "written_context_limit": 15 }
   ```

3. **Backend Routes (routes_vol_expand.py)**:
   - Validate Vol 2 exists, node_type == "volume"
   - Check existing chapter_plan children (none → pass idempotency)
   - Build context: `ctx, editorial_block = build_vol_expand_ctx(db, project, vol2_node)`
   - Query written summaries from Vol 1 (ch 1-10 completed)
   - Query memory chunks (12 most recent)
   - Query open promises (7 unfulfilled)

4. **Context Assembly (context_vol_expand.py → tier modules)**:
   - Tier 1: Positioning (100% face_slap, medium emotional_arc)
   - Tier 1: Power system (9 ranks defined)
   - Tier 1: World settings (5 key settings)
   - Tier 2: Cast (protagonist realm_start → "金丹初期", realm_end → "金丹中期")
   - Tier 2: Relations (love triangle, rivalries)
   - Tier 3: Storylines (main, romance, antagonist - progress per line)
   - Tier 3: Foreshadow ledger (7 active seeds: 3 plant, 2 heat, 2 payoff)
   - Tier 3: Reader promises (8 open: "by vol 2 ch 15 establish romance", etc.)
   - Tier 4: Vol 1 ending state, BOSS realm
   - Tier 5: Pacing stats (vol 1 avg 2200 wds/ch, 85% face_slap density)

5. **Generation (gen_vol_chapter_plans)**:
   - Single batch: chapters 1-30
   - Inject vol 1 hook (ch 30's ending): "主角被迫欠了大敌一条人命"
   - System prompt: 30-year editor persona
   - Prompt assembly: 12K tokens of context + 5K structure template = 17K total
   - Call AI with max_tokens=32768

6. **AI Response** (JSON array, 30 items):
   ```json
   [
     {
   ```
