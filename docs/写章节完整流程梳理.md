# 写章节完整流程梳理

> 本文档梳理 Novel System 中「章节写作」的完整调用链路，涵盖三条写作路径、每一步的提示词模板、注入的信息来源、以及各字段的截取规则。

---

## 一、三条写作路径总览

| 路径 | 端点 | 特点 |
|------|------|------|
| **普通起笔/续写** | `POST /api/v1/projects/{pid}/ai/draft-assist/stream` | 单次生成，无质量门控循环 |
| **门控写作（Gated Draft）** | `POST /api/v1/projects/{pid}/ai/gated-draft-stream` | 写稿→质检→不达标则重写→循环至通过或暂停 |
| **三层调度（Scene）** | `POST /api/v1/projects/{pid}/ai/scene-plan-save`、`scene-draft/stream`、`scene-stitch` | 章纲→分场→逐场正文→拼合 |

三条路径**共享**同一个上下文构建器 `_build_draft_context()`（位于 `draft_routes.py`）和同一个核心生成函数 `draft_assist_stream()`（位于 `services/ai/draft_stream.py`）。

---

## 二、路径 1：普通起笔/续写 `draft-assist/stream`

**入口**：`draft_routes.py` → `draft_assist_stream()` 端点

### 调用链

```
1. 加载 Chapter + Project
2. _build_draft_context() → 组装全部上下文（30+ 字段）
3. merge_writing_config() + prewrite_gate_violation() → 写前硬门检查（不通过返 409）
4. [可选] resolve_pre_write_brief_for_draft() → 写前预警（若 pre_write_warning_enabled=True）
5. svc.draft_assist_stream(**ctx, user_prompt=..., pre_write_brief=...) → 核心生成，SSE 流式输出
```

---

## 三、路径 2：门控写作 `gated-draft-stream`

**入口**：`gated_draft_routes.py` → `gated_draft_stream()` 端点

### 调用链

```
1. 加载 Chapter + Project
2. _build_draft_context() → 同一个上下文构建器
3. _build_location_context() → 空间连续性约束
4. prewrite_gate_violation() → 写前硬门
5. [可选] resolve_pre_write_brief_for_draft() → 写前预警
6. 循环（最多 max_rewrite_attempts 次，默认 3 次）：
   ├── 第1轮: strategy = "initial"（首次起笔）
   ├── 第2轮: strategy = "patch"（定点修复失分维度）
   └── 第3轮: strategy = "full_rewrite"（全量重写）
   
   每轮内部：
   a. [重写轮] _build_rewrite_prompt() → 将上轮质检结果注入 user_prompt
   b. svc.draft_assist_stream(**draft_ctx, replace_existing=True) → 生成正文
   c. _save_chapter_content() → 保存 HTML + 创建 ChapterVersion 快照
   d. _run_quality_check_inline() → 内联质检
   e. _check_passed() → 检查 overall_score / subscribe_intent / face_slap_payoff
   f. 通过 → gate_passed，退出循环
   g. 未通过 → rewrite_queued，进入下一轮
7. 全部耗尽仍未通过 → chapter.status = "needs_review"
```

### 门控通过条件

- `overall_score >= min_overall_score`（默认 6.0）
- `subscribe_intent >= min_subscribe_intent`（默认 6.0）
- 若开启 `enforce_face_slap_payoff_when_hook_required` 且本章为爽点结算章：`face_slap_payoff >= min_face_slap_payoff_score`

---

## 四、路径 3：三层调度（Scene-Based）

### 第一层：场景规划 `scene-plan-save`

- 读取 OutlineNode、Character、Locations
- 计算 `chapter_ingredients`（故事线、债务、伏笔、势力、资产）
- 调用 `svc.scene_plan()` → 生成 4-8 个结构化场景的 JSON
- 持久化 Scene 记录到数据库

### 第二层：逐场写作 `scene-draft/stream`

- 加载 Scene + OutlineNode + Project
- 获取 POV 角色名、在场角色列表
- 获取上一场结尾钩子（order - 1）
- 语义记忆检索（6 条，`embedding_service.semantic_search`）
- `_build_single_location_block()` → 感官约束
- `build_scene_constraint_block()` → 故事线/势力/资产/伏笔/债务约束
- 调用 `svc.scene_draft_stream(...)` → 流式生成单场正文
- 完成后写入 `scene.content`，设置 `status="written"`

### 第三层：拼合 `scene-stitch`

- 按 order 拼接所有已写场景的 content
- 写入 `chapter.content`
- 异步触发 `verify_scenes_after_stitch()`（场景清单 AI 核验）

## 五、共享上下文构建器 `_build_draft_context()`

**位置**：`routers/ai/draft_routes.py` 第 73 行

这是所有写章路径的核心。它从数据库中组装 30+ 个字段，返回 dict 直接作为 `draft_assist_stream()` 的参数。

### 注入的全部数据项

| 数据项 | 数据来源 | 截取规则 |
|--------|----------|----------|
| `chapter_title` | `chapter.title` | 无截取 |
| `outline_hook` | `OutlineNode.hook` | 无截取 |
| `outline_summary` | `OutlineNode.summary` | 无截取 |
| `outline_conflict` | `OutlineNode.conflict` | 无截取 |
| `outline_highlight` | `OutlineNode.highlight` | 无截取 |
| `outline_foreshadow` | `OutlineNode.foreshadows_laid/resolved`，格式化为 `埋[...]  收[...]` | 各取前 3 条 |
| `outline_power_milestone` | `OutlineNode.power_milestone` | 无截取 |
| `outline_emotional_tone` | `OutlineNode.emotional_tone` | 无截取 |
| `story_day` | `OutlineNode.extra.story_day` | 无截取 |
| `chapter_manifest` | 出场人物名单（从 `involved_character_ids` 解析） | 无截取 |
| `premise` | `Project.premise` | `_clip_context(1200, 12000)` |
| `world_summary` | 所有 `WorldSetting` 记录，`format_world_setting_context()` | 每条 `content_limit=2400` 字 |
| `character_summary` | `_build_character_summary()` 构建 | 详见下方专项说明 |
| `storyline_summary` | 活跃故事线（planned/active/climax） | `core_conflict` 截取 500 字，`key_beats` JSON 截取 1600 字 |
| `memory_summary` | RAG 语义检索 + 时序锚定 | 语义 top-K=74，时序锚定 6 条；格式化后 `_clip_context(150, 12000)` |
| `prev_chapter_tail` | 上一章正文末尾（纯文本，去索引块） | 最后 3000 字 |
| `existing_content` | 当前章已有正文（续写模式时） | 续写时 `_clip_context(500, 4000, from_end=True)` |
| `continuity_context` | `build_continuity_context()` | `_clip_context(2000, 24000)` |
| `chapter_index_context` | `build_chapter_index_context()` | `_clip_context(1600, 20000)` |
| `writing_brief_context` | `build_writing_brief_context()` + 多项追加 | `_clip_context(1200, 20000)` |
| `plot_dossier_context` | `build_plot_dossier_context()`（开局期跳过） | `_clip_context(2200, 30000)` |
| `quality_debt_context` | `build_quality_debt_context()`（开局期跳过） | `_clip_context(1200, 12000)` |
| `reader_promise_context` | `_build_reader_promise_context()` | `_clip_context(800, 6000)` |
| `scene_blueprint` | `_build_scene_blueprint()` | `_clip_context(800, 6000)` |
| `prev_directives` | `OutlineNode.extra.directives_from_prev`（来自上章复盘） | 无截取 |
| `realm_snapshot` | 人物当前境界 `{name: current_realm}` | 最多 8 个人物 |
| `positioning` | `Project.extra.positioning` 或 `Project.story_core.positioning` | 原 dict，不截取 |
| `phase` | `OutlineNode.phase` 或父卷的 `phase` | 字符串 |
| `word_target` | `OutlineNode.expected_words` / `extra.word_estimate`，默认 2300 | 整数 |
| `pov_character_name` | `OutlineNode.pov_character.name` | 无截取 |
| `character_screen_time` | `OutlineNode.character_screen_time` | dict |
| `genre` | `Project.genre` | 字符串 |

### `_clip_context(local_limit, gemini_limit, from_end=False)` 说明

这是统一截取函数，根据模型上下文容量选择截取长度：

- 第一个参数 = 本地小模型截取限制
- 第二个参数 = 远程大上下文模型（Gemini 等）截取限制
- `from_end=True` 时从文本末尾截取（用于上章结尾、已有正文等需要尾部的场景）

**当前部署仅使用远程线路**，所以实际生效的是第二个参数（gemini_limit）。

## 七、continuity_context 详细构成

**位置**：`services/ai/context_builder.py` → `build_continuity_context()`

生成结果为一个事实账本字符串，包含以下部分（按顺序拼接）：

| 部分 | 内容 | 截取 |
|------|------|------|
| 人物状态 | 前 10 个人物的 `name / role / current_realm / realm_rank / current_location / current_status` | 10 人上限 |
| 力量体系 | 前 3 个 `PowerSystem` 的 `levels[0:8]` + `protagonist_current_rank` + 规则 | 3 个体系，每条规则截取 80 字 |
| 最近章节 | 倒数 3 章的 `summary` 或 `content` 尾部 | 每条 160 字 |
| 记忆/伏笔 | 最近 8 条 `MemoryChunk`（类型 = foreshadow/event/character_state） | 每条 100 字 |
| 未回收伏笔 | 全局 open 伏笔（逾期优先→priority 降序→时间升序） | 前 12 条，描述截取 60 字 |
| 故事线进度 | 前 5 条活跃故事线的最后一个 beat | 每条 90 字 |
| 承接点 | 上章衔接要求 + 实力目标 + 伏笔因果 | 无截取 |
| 禁止事项 | 境界不倒退、无信息穿越、不跳过钩子反应 | 固定文本 |
| 一致性矛盾 | `Project.extra.consistency_issues` 按人物清单筛选 | 追加到 continuity_context 末尾 |

## 八、RAG 记忆检索

**位置**：`services/rag_retrieval_service.py` → `retrieve_and_log_draft_context()`

### 章节写作检索

| 参数 | 值 |
|------|-----|
| **Query** | `outline_node.summary + conflict + highlight`，或 `chapter.title` |
| **语义检索 top-K** | 74（远程大上下文） |
| **时序锚定** | 最近 6 条（按 `chapter_number DESC`） |
| **去重策略** | 语义命中优先，时序补空位 |
| **max_chapter** | 当前章 `sort_order`（防未来章剧透） |
| **Embedding 模型** | BAAI/bge-m3（1024 维），pgvector 向量检索 |
| **降级** | pgvector 不可用时按 `importance_score DESC + chapter_number DESC` |
| **日志** | 每次检索落库 `rag_retrieval_log`（含 hits/status/duration_ms） |

### 场景写作检索

| 参数 | 值 |
|------|-----|
| **Query** | `chapter_title + scene.goal + scene.conflict` |
| **top-K** | 6 |
| **方式** | 直接 `semantic_search`，无时序锚定 |

## 九、核心提示词模板——整章写作 `draft_assist_stream()`

**位置**：`services/ai/draft_stream.py` → `DraftStreamMixin.draft_assist_stream()`

### 9.1 System Prompt 结构

```
你是拥有30年经验的网络小说作家，文笔老练，深谙追读节奏。
你的任务是根据章节计划与故事背景，输出一段高质量的本章正文。

【核心写作原则】
1. 严格落实「开篇钩子」意图，第一句话就要抓人
2. 世界观与人物当前境界、状态、技能须与既有设定吻合，不得矛盾
3. 人物的行动、心理须符合其弧线、动机、价值观；既有故事线必须顺势推进
4. 上一章结尾、本章实力里程碑、情感基调要有分量地接续
5. 直接给出正文：不要解释、不要旁白……不要 AI 自指词

{genre_guardrail}          ← 类型护栏（玄幻词汇黑名单等）
{positioning_brief}        ← 作品基本面（目标读者/核心爽点/打脸频率/情感线占比/节奏类型/卖点钩子）
{phase_brief}              ← 卷阶段指令（opening/rising/turning/dark_hour/climax/ending）
{prev_directives}          ← 上一章复盘闭环指令（最高优先级）
```

### 9.2 卷阶段指令 `phase_brief` 详情

| phase | 关键指令摘要 |
|-------|-------------|
| **opening** | 钩子密度高（800-1000 字一个张力点）；200 字内落地世界/主角/痛点；3 章一小爽；字数偏短（~2200）；对话 40%/行动 40%/心理 20% |
| **rising** | 势力扩展、感情线接入；保留 hook；允许中等铺垫；对话 35%/行动 40%/心理 25% |
| **turning** | 矛盾升级；反转或代价兑现；不回避负面情绪；对话 35%/行动 35%/心理 30% |
| **dark_hour** | 允许虐，节奏放缓；主角处境恶化不急反弹；字数拉长（~2800）；心理 40%/行动 35%/对话 25% |
| **climax** | 伏笔必须给反馈；爆点拉满（动作/情绪/信息揭示三选二）；字数 3000-3300；行动 55%/对话 30%/心理 15% |
| **ending** | 交代感但保留下卷悬念种子；不要总结性独白；行动 40%/对话 35%/心理 25% |

```
【立意与类型 / PREMISE】
{premise}                          ← _clip_context(1200, 12000)

【故事背景】

{continuity_context}               ← _clip_context(2000, 24000)
{chapter_index_context}            ← _clip_context(1600, 20000)
{plot_dossier_context}             ← _clip_context(2200, 30000)

```

### 9.4 `final_reminder` 写作硬约束块

这段放在 user prompt 最末尾，紧贴生成指令，召回率最高：

```
【⚠️ 写作前最后重读（违反任意一条视为本章不合格）】

▍章末钩子（最后一段 ≤80 字，必须满足以下之一）
A) 出现新的未解之谜或揭示
B) 强敌 / 关键 NPC 登场但未交手
C) 关键人物开口未说完，话被掐断
D) 主角被推到决策悬崖
严禁章末用总结句、抒情句、陈述性收束

▍严禁清单
- 流水账连接词：「然后…接着…于是…此时…」
- 排比式抒情开篇
- 单段心理独白超过 200 字
- 解释性旁白连续 3 句以上
- 滥用「突然」
- AI 自指词

▍截图时刻（每章至少 1 处）
A) 狠话档    B) 细节档    C) 反转档

▍每一场戏都必须服务作品基本面

▍强制 POV：{pov_character_name}（有值时注入）
▍戏份预算（建议 ±5%）：{character_screen_time}
▍配角配额：主1 + 核心配角3 + 反派2 + 师长2

▍境界状态锁定（⚠️ 最高级别约束）
  {name}：当前境界={realm}（绝对禁止降级）
  ...
```

## 十一、重写提示词模板

**位置**：`gated_draft_quality.py` → `_build_rewrite_prompt()`

### 11.1 Patch 策略（第 2 轮）

```
===【质量门控 · 第{attempt}轮 · 定点修复 PATCH】===
上轮整体得分：{overall}/10，未达门槛。本轮只修**失分维度**，其余结构**原样保留**。

▍失分维度（本轮唯一修复目标）：
  • {dim_name}（{score}分）：{comment}

▍针对失分维度的具体修复项（按维度关键词匹配，最多 4 条）：
  1. {targeted_suggestion}

▍一致性/钩子问题（前 3 条）：
  • {issue_description}

▍强维度（禁止触动）：{≥8 分的维度名}
这些维度所在段落逐字保留或等义改写，不要重新构思。

PATCH 约束：
- 修改范围控制在失分段落；强维度段落保持稳定
- 保持相同 POV、叙事节奏、人物口吻
- 禁止引入新主线、新角色、新伏笔
===
```

### 11.2 Full Rewrite 策略（最后一轮）

```
===【质量门控 · 第{attempt}轮 · 全量重写 FULL REWRITE】===
⚠️ 上轮得分 {overall}/10，前几轮定点修复均未达标。
本轮请彻底重构本章结构，允许推翻场景顺序、POV 切换点、章末钩子设计。

▍必须解决的全部问题（前 6 条）：
  • {issue_description}

▍全部编辑建议（每条须在正文中对应落地，前 10 条）：
  1. {suggestion}

▍重构硬约束：
- 章末最后一段必须是强钩子
- 人物境界/位置/持有物必须与情节档案吻合
- 打脸/爽点以具体场景动作落地
- 允许调整分场顺序与详略分布
- 正文总字数控制在大纲预算 ±15% 内
===
```
