# 番茄·修仙打脸流 Bootstrap 链路设计

> 状态：设计稿（待评审 → 实现）｜作者：AI｜日期：2026-06-06
> 决策前置：交付形态＝**设计文档先行**；境界轴＝**单主轴 + 小境**。
> 适用范围：`mode=fanqie` 且 `genre_archetype` 落在「修仙打脸流」（含古武觉醒/星际无敌中带境界轴的变体）。

---

## 0. 一句话结论

现有番茄线对都市/赘婿是对的，对修仙是**结构性错配**：它把「社会五阶」当成全书唯一境界轴，并用黑名单**封禁了修仙的母语词汇（筑基/金丹/元婴…）**。修仙的爽感引擎恰恰是境界体系本身。

解法不是新开第四条平行栈，而是在**番茄图内按类型条件切换一个境界轴生成 step**（diverge upstream），产物仍归一化进同一套 `PowerSystem` / `power_ladder` ctx 契约（converge downstream）。改动集中在 1 个新 step + 1 处策略改造 + 3 处条件分叉，全部 ≤600 行红线内。

---

## 1. 现状诊断（为什么修仙会崩）

| 环节 | 现状实现 | 对修仙的问题 |
|---|---|---|
| `power_ladder.py`（Step 9） | prompt 生成 `social_ladder` 五阶，示例全是「豪车+私人司机/酒店包场/随手打赏百万」 | 修仙要的是**境界**（8-12 大境×小境×宗门秘境天材地宝），五个社会阶层既不够档位、画风也跑成都市 |
| `fanqie_realm_policy.py` | 把 `social_ladder` 注水成**全书唯一合法主轴**；`build_fanqie_realm_discipline_block` 用 `TRADITIONAL_CULTIVATION_BLACKLIST` **封禁筑基/金丹/元婴/斗气体系等全部境名** | 修仙正文一旦写「突破金丹」就被规范化器打回最低档；等于禁掉了类型母语。黑名单的初衷（防套话）对都市成立，对修仙是误伤 |
| `fanqie_formula.py`（落差+金手指+打脸地图） | `_FINGER_TYPES` 偏都市（系统面板/空间戒指/签到/鉴宝/医术觉醒） | 修仙金手指应是**功法/丹炉/灵根/吞噬/老爷爷/天眼/重生**这一脉；都市金手指会让世界观分裂 |
| `power_ladder` 财富/战力可视化 | `wealth_visualization` / `power_visualization` 二元 | 修仙要的是**境界压制可视化**（气血/灵压/法则气息/一招破敌），不是财富 |
| 卷级对立面 `antagonist_ladder` | 通用，Boss 用社会身份 | 修仙 Boss 应锚定**境界差**（每卷主角境界 vs Boss 境界、压制与翻盘） |
| `settings` 番茄精简 3 卡 | 「主角起点生存环境/世界底层规则/资源经济」 | 修仙至少要 1 张**修炼资源生态卡**（灵气/灵石/丹药/功法品阶/宗门），否则金手指无处生根 |

**根因**：番茄线把「境界轴」硬编码为「社会阶梯」，对非修仙类是优化（少 token、画面直白），对修仙类是阉割。

## 2. 设计目标与原则

1. **类型母语优先**：修仙必须有一条命名鲜明、读者一眼能懂、又有正统修仙感的境界主轴；放开（而非封禁）境界词汇，但要求**自创/差异化命名**避免套话。
2. **爽感引擎对齐境界**：落差、金手指、打脸、卷级 Boss、节奏全部锚定「境界差」这条主轴，而不是财富/社会身份。
3. **不开第四条栈**：复用 `mode=fanqie` 与 `get_graph_for_mode`，在图内按 `genre_archetype` 条件分叉，产物归一化进通用 `PowerSystem`。
4. **番茄铁律不破**：金手指 ≤800 字触发、首次打脸 ≤第5章、爽点密度、低阅读门槛（`writing_style=plain`）全部保留。
5. **红线兼容**：新增逻辑落到新文件（`steps/fanqie/cultivation_ladder.py` 等），不往登记册上帝文件加行；单文件 ≤600。
6. **单主轴 + 小境**（本次决策）：一条主境界轴，每大境含「初期/中期/后期/圆满」四小境；暂不做丹道/炼器/肉身多副轴，降低写作期一致性维护成本。

## 3. 链路总览（修仙专属拓扑）

在现有 `graph_fanqie.py` 拓扑上做**最小条件分叉**。带 ★ 的是修仙改动点。

```
Phase A  立项
  fanqie_positioning → gate → project
Phase B  爽文公式
  → fanqie_formula ★(金手指类型库切修仙)
  → power_axis ★★(条件分叉：修仙→cultivation_ladder / 其余→power_ladder)
  → ctx_bridge
Phase C  世界构建
  → factions ★(注入「宗门/势力按境界分层」提示)
  → storylines → antagonist_ladder ★(Boss 锚定境界差)
  → characters → gate_characters
  → skills_items ★(功法绑定境界阶) → settings ★(+1张修炼资源生态卡)
Phase D  卷级结构
  → volumes ★(每卷标注主角起止境界) → gate_volumes
Phase E  节奏 + 情绪
  → emotion_villain → rhythm_map ★(big_win 锚点含「破境」)
Phase F  记忆 / 伏笔 / 承诺
  → memory_relations → promise_seeds
Phase G  校验
  → signal_audit ★(+境界曲线单调性/破境密度规则)
  → END
```

**分叉点只有一个真正的新节点**：`power_axis`（Phase B 内，替代 `node_power_ladder`）。其余 ★ 都是在已有 step 的 prompt/ctx 里按 `is_xianxia(ctx)` 注入一段修仙约束，不新增 LLM 调用。

`is_xianxia(ctx)` 判定：`fanqie_positioning.genre_archetype` 含「修仙/仙侠/修真」或显式 `cultivation_axis=True`。落库到 `Project.extra.fanqie_axis_kind ∈ {"cultivation","social"}` 供写作期重跑恢复。

## 4. 境界轴策略（核心设计）

### 4.1 数据契约（与现有完全兼容）

修仙轴产物必须填满与 `power_ladder` **相同的 ctx 键**，这样 `hydrate_fanqie_power_ctx` / `sync_power_ladder_to_power_system` / `build_fanqie_realm_discipline_block` 一行不改即可复用：

```jsonc
// ctx['power_ladder'] —— 沿用同一个键名，仅语义切换为境界轴
{
  "axis_kind": "cultivation",
  "world_core_rule": "灵气复苏后，境界即一切话语权；低境者在高境者面前连呼吸都被压制",
  "realm_axis_name": "自创主轴名（如「九转归元境」，禁止照搬筑基金丹元婴」）",
  "social_ladder": [                       // 复用 social_ladder 键 = 大境数组
    {"tier": 1, "name": "<大境1名>", "description": "<这一境的体感/能做什么，15字>", "representative": "主角起点"},
    {"tier": 2, "name": "<大境2名>", "description": "...", "representative": "..."},
    // ... 8-12 档
    {"tier": 10, "name": "<顶境名>", "description": "...", "representative": "终极Boss/主角终态"}
  ],
  "sub_realm_segments": ["初期","中期","后期","圆满"],   // 小境写法
  "protagonist_start_tier": 1,
  "protagonist_end_tier": 10,
  "power_visualization": "境界压制画面（如：高一境者一念之间，低境者灵力溃散、跪伏在地）",
  "wealth_visualization": "修炼资源差距画面（如：灵石如雨/丹药管够 vs 主角连一块下品灵石都凑不齐）",
  "setting_vibe": "灵气复苏现代 / 古典仙门 / 星际修真（10字内）",
  "breakthrough_signature": "破境的统一外显（如：天降异象、灵气漩涡、心魔劫）"
}
```

> 关键：`social_ladder` 这个键名**保持不变**（避免改 `hydrate_fanqie_power_ctx` 与 normalize），但语义从「社会阶层」切成「大境」。`tier` 即 rank（1-based，低→高），直接喂 `PowerSystem.levels[].rank`。

### 4.2 大境数量与小境

- **大境 8-12 档**（推荐 9-10）：低于 8 撑不起长线打脸升级，高于 12 后期注水。主角 `start_tier=1`、`end_tier=` 顶档或次顶档（留一档给最终 Boss/续作）。
- **小境固定四段**：初期/中期/后期/圆满。写作期境界写法 = `<大境名><小境>`（如「淬体境后期」）。`build_fanqie_realm_discipline_block` 已支持这种「大境+后缀」写法，无需改。

### 4.3 黑名单策略改造（关键修复）

现状：`build_fanqie_realm_discipline_block` 把 `TRADITIONAL_CULTIVATION_BLACKLIST` 里**不在 level 列表中**的境名全禁。对都市这是对的；对修仙，如果生成的主轴自创得好，黑名单本就只禁「主轴之外的套话境名」，逻辑**天然成立**——只要生成 step 产出一条**自洽且不照搬**的主轴，纪律块就替修仙服务，而不是反对它。

需要的两处微调：

1. **生成端去套话**：`cultivation_ladder` 的 prompt 强约束「主轴命名必须自创，禁止直接用筑基/金丹/元婴/斗气九段等公版词作为大境名；可用其语感但要换字」。这样落库的 `social_ladder` 名字本身就绕开黑名单。
2. **纪律块参数化**：`build_fanqie_realm_discipline_block(level_names, axis_kind="cultivation")`，修仙模式下 banned 列表**只保留与本书主轴冲突的公版套话**，并把提示语从「禁止任何修真境名」改为「禁止使用**本书主轴之外**的境名套话」。避免误伤正文里合理的修仙术语（如「灵气」「破境」「心魔劫」这些非境名词）。

> 落地点：`fanqie_realm_policy.py`（登记册外，可改），新增 `axis_kind` 形参，默认行为对 social 轴完全不变（向后兼容）。

### 4.4 落库归一化

`sync_power_ladder_to_power_system` **已经**把 power_ladder 落成 `system_type="cultivation"` 的 PowerSystem，名字叫「…·修炼阶梯」。修仙轴几乎零改：
- `name` 改用 `realm_axis_name`（有则用，无则回退原命名）。
- `breakthrough_condition` 填 `breakthrough_signature`。
- `levels[].name` = 大境名；小境不落 PowerSystem（保持 rank 干净），仅作为写作期写法约定。

## 5. 逐 Step 设计

### 5.1 ★★ 新增 `steps/fanqie/cultivation_ladder.py`（核心新文件）

替代 `power_ladder` 的修仙版。一次 LLM 调用，产物填 §4.1 契约。

**Prompt 要点**（system：番茄修仙世界架构师，只返回 JSON）：
- 输入：`project_title` / `genre_archetype` / `golden_finger`（finger_name + ceiling）/ `face_slap_map.escalation_path` / `logline`。
- 硬约束：
  1. 主轴 8-12 大境，低→高单调，主角从第1档打到顶/次顶档。
  2. **命名自创**：禁止直接用「练气/筑基/金丹/元婴/化神/斗者…斗帝」等公版词作大境名；可保留「淬体→通脉→凝罡→…」式语感但需换字成本书专名。
  3. `world_core_rule` 一句话、读者立刻懂、且**让境界差有意义**（决定打脸成立）。
  4. `power_visualization` 必须是**境界压制画面**（第1章就能出现），不是财富。
  5. 每大境 `description` ≤15字、给「这一境能做到什么」的体感，不写历史掌故。
  6. `breakthrough_signature` 给破境的统一外显（异象/劫云/灵潮），供卷纲反复调用造爽点。
- 校验 `_validate`：`social_ladder` ≥8 且 ≤12；主轴名非空且不在公版黑名单整词命中；start_tier=1。

**与下游衔接**：调用末尾照抄 `power_ladder` 的收尾——
```python
extra["power_ladder"] = data; extra["fanqie_axis_kind"] = "cultivation"
hydrate_fanqie_power_ctx(ctx)             # 复用，零改
sync_power_ladder_to_power_system(db, project)  # 复用，name 用 realm_axis_name
```

### 5.2 ★ Phase B 分叉节点 `node_power_axis`（改 `graph_fanqie.py`）

```python
async def node_power_axis(s, c=None):
    if is_xianxia(_ctx_of(s)):
        from ...steps.fanqie.cultivation_ladder import gen_cultivation_ladder
        return await _fanqie_step(s, c, "power_axis", "构建修仙境界主轴（8-12大境×小境）...", gen_cultivation_ladder)
    from ...steps.fanqie.power_ladder import gen_power_ladder
    return await _fanqie_step(s, c, "power_axis", "构建权力阶梯（最小化世界观）...", gen_power_ladder)
```
graph 里把原 `power_ladder` 节点替换为 `power_axis`。单步重跑表里 `power_ladder` → `power_axis` 别名兼容。

### 5.3 ★ `fanqie_formula.py` 金手指类型库分叉

不新增调用，仅在 prompt 内按类型切 `_FINGER_TYPES`：
```python
_FINGER_TYPES_XIANXIA = (
    "吞噬/炼化体质 / 万界功法图书馆 / 极品灵根觉醒 / 上古传承（剑修/丹尊/体修）/ "
    "随身丹炉空间（种灵药/炼丹） / 重生归来（知道天材地宝/秘境位置） / "
    "神识天眼（鉴宝/看穿境界/破阵） / 时间加速闭关 / 杀伐证道（杀敌爆修为）"
)
```
落差 `humiliation_scenes` 改修仙语境（灵根被废/被逐出宗门/筋脉尽断/未婚妻退婚改投天骄）。`final_destination` 锚定境界终态。

### 5.4 ★ `antagonist_ladder`（卷级对立面，注入境界差）

每卷 Boss roster 增加字段提示：`boss_realm`（用主轴大境名）、`gap_to_protagonist`（开卷时主角落后几档）、`reversal_trigger`（靠金手指/秘境奇遇/破境翻盘的具体抓手）。让「越级打脸」可量化、可校验。

### 5.5 ★ `skills_items` + `settings`

- 功法 `Skill` 绑定 `min_realm`（可施展的最低主轴大境），道具 `Item` 标 `realm_tier`（适配境界段）。让金手指升级与境界破境呼应。
- settings 番茄 3 卡中，把「资源经济与稀缺机制」具体化为**修炼资源生态卡**：灵气/灵石/丹药品阶/功法品阶/宗门与秘境，一张卡讲清「主角靠什么破境、稀缺在哪」。其余两卡（起点生存环境/世界底层规则）保留。

### 5.6 ★ `volumes` 每卷境界标注

`gen_volumes` 的卷骨架 extra 增 `realm_window`：`{start_realm, end_realm}`（主轴大境名）。配合 `power_timeline_table_v1` 形成卷级战力时间轴，写作期 `realm_timeline` 校验直接吃这套。

### 5.7 ★ `rhythm_map` / `signal_audit` 破境锚点

- rhythm_map：`_build_chapter_tags_by_rule` 已从金手指 `upgrade_stages.chapter_range` 取 big_win；修仙下把「升级」语义对齐「破境」，确保每个 `upgrade_stage` 对应一次破境爽点。
- signal_audit（规则版，零 token）：新增两条修仙规则——
  1. **境界单调性**：`social_ladder` rank 严格递增、主角 start<end，否则 issue。
  2. **破境密度**：前 50 章 big_win 中「破境类」≥3 次，否则提示「修仙线缺破境爽点」。

2. PowerSystem `extra.axis_kind = "cultivation"`、`extra.sub_realm_segments`（写作期组装小境写法用）。

写作期（卷纲展开/写章/复盘）已有的 `build_fanqie_realm_discipline_block` 注入链路**全部不动**，只是它现在锁的是一条真正的修仙主轴，方向从「反对修仙」变成「保护修仙一致性」。

## 10. 风险与取舍

1. **自创境名 vs 读者熟悉度**：完全自创可能牺牲「一眼懂」。折中——主轴名自创，但 `description` 用通俗体感词描述，且第1章正文用「相当于传统筑基」类锚点降低门槛（plain 风格本就允许就近解释）。
2. **单主轴的天花板**：放弃丹道/炼器副轴会损失一部分修仙读者的「多线养成」爽感。本次按决策取单主轴换一致性；副轴可作为后续 `axis_kind="cultivation_multi"` 扩展，契约已为多轴预留（`power_systems_full` 本就是数组）。
3. **黑名单参数化的回归风险**：改 `build_fanqie_realm_discipline_block` 影响所有番茄书。务必让 `axis_kind="social"` 为默认且行为 100% 不变，仅修仙显式传 `"cultivation"`，并补单测覆盖两条路径。
4. **`graph_fanqie.py` 行数**：加节点前先 `wc -l`，若逼近 600 则把分叉工具 `is_xianxia` / `_ctx_of` 抽到 `graph_fanqie_enhance.py` 或新 `fanqie_axis.py`。
