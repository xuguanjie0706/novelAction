## 一、本批已有改动的定位（你做了什么）

这批改动主线是「连续性 / 可信度」，本质是同一个模式——**台账落库 → 写章期注入硬约束**：

| 模块 | 作用 |
|---|---|
| `draft_continuity_bridge.py` | 跨章防倒带：锁定上章已完节拍，禁止「再觉醒一次/再休一次妻」 |
| `narrative_knowledge.py` | 认知边界台账：谁已知道哪些专名，防旁白「科普式」剧透点名 |
| `context_queries.format_character_block` | 把 `speech_style` 注入人物块（语风锚点） |
| `vol_chapter_plans_prompt` | 章纲层禁倒带：`opening_hook` 不得重播上章 `end_hook` |
| `fanqie_normalize` | 番茄线回填 `opening_contract`，补追读命脉 |

这条线解决的是「不出戏、不穿帮」——**及格线**。但番茄的留存命脉是**完读率 + 追读率**，「不穿帮」之上还有「读起来像不像人写的爽文」这一层没覆盖。

> **认知台账闭环缺口**：`merge_narrative_knowledge_from_debrief` 目前仅在**手动复盘且 chapter_index 落库**时触发；队列 `queue_auto` 未接，未复盘项目的认知边界可能长期停留在 Bootstrap 默认。

## 二、本次落地的优化（零额外 LLM）

下列三项**全部不新增任何 LLM 调用**：要么是对「已写正文 / 已有结构化字段」的纯代码统计，要么是对**现有 draft prompt** 的内容增强（同一次写章调用，不多发请求）。

### 优化 1 ｜反「AI 腔」套话去重（纯统计，零 LLM）

**问题**：AI 网文最大的「一眼假」不是穿帮，是跨章累积的同质化句式——「嘴角勾起一抹弧度」「一股暖流涌上心头」「心中一凛」反复出现。`draft.chapter` 的 frequency/presence_penalty 只能压**单章内**重复，压不住**跨章**口头禅。

**方案**：写章前，对「当前章之前最近 6 章已写正文」做正则计数：
- **套话库命中**：命中 ≥2 个不同章节，或总命中 ≥4 次 → 列入「本章禁用清单」；
- **句首词频**：跨章出现 ≥5 次的「句首三字」（如「他知道…」）→ 列入「本章需变换」清单；
- 把清单作为硬约束注入 draft prompt：「本章禁止再用以下已被用滥的套话／句首」。

**关键点**：清单是**数据驱动**的——只禁真正高频出现的，不命中不污染 prompt，避免误伤偶发用词。

**落点**：
- 新增 `apps/backend/app/services/ai/draft_style_guard.py`（278 行，新 capability 文件，符合「新 AI 能力走 `services/ai/<capability>.py`」红线）
  - 纯逻辑（可独立单测，无 DB/LLM）：`scan_cliches` / `scan_sentence_openers`
  - DB 取数 + 组装：`build_anti_ai_tic_block`
- 注入点见「优化 3」（统一走 bridge 聚合）

**伪代码**：
```python
def scan_cliches(texts: list[str]) -> list[str]:
    flagged = []
    for name, pat in _CLICHE_PATTERNS:
        total, chapters_hit = 计算命中(texts, pat)
        if chapters_hit >= 2 or total >= 4:      # 只锁定真正高频
            flagged.append((name, total, chapters_hit))
    return [f"{name}（近{ch}章共{tot}次）" for ...]   # 按热度降序
```

### 优化 2 ｜打脸具体化 + 围观反应（纯 prompt，零 LLM）

**问题**：番茄爽感的真正引擎是**配角/吃瓜群众的反应衬托**——打脸要写对方脸色、围观者惊呼、具体台词。AI 默认会写抽象（「场面一时哗然」「众人震惊」），恰恰丢掉读者最想看的部分。

**方案**：在 `draft_stream.py` 的 **plain 分叉「白话直白硬要求」**里追加两条硬约束（不新增调用，只改提示词）：
- 打脸/反转必写被打脸者脸色/动作/原话 + ≥1 句围观反应，禁止「场面一时哗然」一笔带过；
- 关键场面给镜头：具体动作/对话/感官细节，杜绝「气氛很紧张」「实力差距巨大」式抽象总结。

**落点**：`apps/backend/app/services/ai/draft_stream.py`（plain `_forbid_block` 同段，仅 plain 生效，不影响 standard/dense）。

### 优化 3 ｜章级「憋屈预算」守门（纯统计，零 LLM）

**问题**：番茄读者耐心极低，连续多章「憋屈/虐」会批量弃书；卷级 `emotion_arc` 拦不住章级的局部憋屈过载。

**方案**：读「近 6 章 + 本章」对应 `OutlineNode.emotional_tone`，统计末尾连续憋屈基调章数：
- 连续 ≥2 章 → 提醒：本章建议安排情绪释放/小爽点；
- 连续 ≥3 章 → 硬约束：本章必须给一次明确小爽点/反转/出口，禁止继续纯憋屈。

**落点**：`draft_style_guard.build_emotion_budget_block`（读已有结构化字段，无 LLM）。

### 注入路径（重要架构决策）

`draft_style_guard` 的两个块**没有**直接写进 `context_assembler.assemble_full`——因为该文件已在 CLAUDE.md「上帝文件登记册」标为 🚫 **禁止继续增入**（600 行红线）。

改为**聚合进 `draft_continuity_bridge.build_draft_continuity_bridge_block`**（锁定节拍 / 语风 / 认知边界 + 风格守门）。装配链路：

```
assemble_full
  → draft_ctx_bridge.resolve_draft_bridge_context   # 薄封装，≤40 行
      → draft_continuity_bridge（含 draft_style_guard）
  → draft_stream（bridge_part，clip 3000 / 9000）
```

- 风格守门作为独立 capability 文件保留（职责清晰、可单测）；
- **`context_assembler.py` 不内联 bridge/style 逻辑**：仅一行调用 `resolve_draft_bridge_context`；超标辅助函数迁至 `context_assembler_helpers.py`；
- draft prompt 注入点不变（`bridge_part`），clip 预算由 2400/8000 上调到 3000/9000 容纳新块。

## 五、风险与回滚

| 风险 | 评估 | 缓解 |
|---|---|---|
| 套话误伤正常用词 | 低～中 | 阈值（≥2 章或 ≥4 次）+ 近 6 章窗口；「仿佛/似乎」类模式较宽，真书观察清单长度 |
| prompt 变长挤占预算 | 低 | 块短小；bridge clip 上限 9000 兜底 |
| 章 1 / 无上一章时 | 无 | bridge 早返 → 无跨章块；风格守门随 bridge 一并跳过 |
| 认知台账未复盘 | 中 | 仅手动 debrief 落库；见第一节缺口说明 |
| 与现有 plain 清单冲突 | 无 | 仅追加；standard/dense 不受打脸条款影响 |

**回滚**：删 `draft_style_guard.py` + 还原 `draft_continuity_bridge` 末尾聚合 + 还原 `draft_stream` plain/clip + 可选删 `draft_ctx_bridge.py`（assembler 改回直接调 bridge 或移除 bridge 字段）。

## 六、后续建议（仍尽量低/零 LLM）

按性价比排序，留作下一批：

1. **语风指纹质检（零增量 LLM，搭车现有 `quality.check`）**：你已注入 `speech_style`，但没校验「对话是否真体现语风/两角色是否撞脸」。在 `quality.py` plain 维度的**同一次调用**里加一个「台词区分度」维度即可，不新增请求。
2. **黄金开篇/首屏门控（搭车现有 quality 调用）**：对前 200 字单独评（钩子前置？视角锚定？信息钩子？），弃书多发生在开头而非结尾。
3. **套话台账持久化（可选）**：当前每次写章实时统计近 6 章；若要全书级口头禅治理，可在复盘期把高频套话落 `Project.extra.style_tics`，写章直接读账（省去实时扫描，仍零 LLM）。
4. **弃书点预测接回写章（你 TODO 已列，需 LLM 但可搭车复盘）**：把段级弃书点预测并入**现有复盘调用**的 JSON 输出，不新增请求，低分段自动转 `next_chapter_directives`。
5. **句首/句长多样性进 quality**：把本次的句首词频统计指标也喂给质检做量化打分，形成「生成约束 + 质检度量」闭环。
6. **queue_auto 接 cognitive 台账**：在自动复盘路径调用 `merge_narrative_knowledge_from_debrief`，闭合认知边界。
