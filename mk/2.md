我基于你已落地的 P0（流派分流 + 复盘闭环 + 三层调度前置）与 P1（语风指纹 + ReaderPromise + 读者模拟器），重新审视了整个一键生成链路。一句话结论：

系统现在已经从“勤奋的设定填表机”进化成了“有流派意识、能闭环驱动下一章、有人物语风记忆、知道对读者承诺过什么”的初级编辑系统，但核心的“分镜-节奏-视点-戏份预算”四道工序仍未真正落地，AI 味和人物漂的问题只是被“缓解”，而非“根治”。

下面按问题严重程度，给出仍需优化的点与方案（全部是编辑视角，不涉及任何实现细节）。

一、仍最致命的根因（P2 必须优先级）
“章纲 → 分场 → 正文”三层调度只做了前两层的前置，第三层（逐场写正文 + stitch）完全缺失
即使有了 genre_kit 和 next_chapter_directives，当前 draft_assist_stream 仍然是“把整章大纲一次性扔给模型写 2200 字”。模型在写第 5 场的时候，已经忘了第 2 场埋的钩子要怎么回收；它不知道“这一段是全章最该快的冲突高潮”还是“该留白的心理过渡”。
编辑视角：真正的网文编辑从来不让作者“直接写正文”。他们先拆 6-8 场，每场给 POV、时间、地点、目标、冲突强度、感官焦点、字数预算、钩子强度，再让作者逐场写。
方案（P2 最高优先级）：把 Scene 做成一等公民。

新增 Scene 概念（即使先不建表，也要在内存里走一层）：每章必须先输出结构化分场（order、location、time、pov_character_id、characters_on_stage、goal、conflict、turn、hook、word_budget、sensory_focus、pacing）。
再按场逐场生成正文，最后 stitch + 自检“本场是否完成了本章承诺的转折”。
写完后增加“分场自检”：POV 是否漂移、配角是否失语、节奏是否符合 genre_kit 的 pacing_guide。
这条不做，后面所有优化都只能让“句子更好看”，但节奏依然是平的。
戏份预算（character_screen_time）与强制 POV 仍未在生成时被真正执行
虽然 speech_kit 已经能沉淀语风，但 draft prompt 里还没有“本章必须给 A 角色 18% 戏份、必须用 B 的 POV 写第 3 场”的硬约束。next_chapter_directives 里有 increase_screen_time_for，但它只是“建议”，模型可以选择性忽略。
方案：

OutlineNode / Scene 强制字段 character_screen_time: {char_id: 百分比} 和 pov_character_id。
生成章纲/分场时，genre_kit 的 side_character_quota 必须被严格遵守（玄幻本章在场角色不得超过 1 主 + 3 核 + 2 反）。
Prompt 末尾加硬约束：“若本章 A 角色戏份低于预算 5%，本章判不合格，必须重写”。
没有这条，5 章后二号女主就会再次“失语”。
伏笔台账仍停留在“记账本”，没有“预算 + 超期告警”
虽然 planned_resolve_chapter 已加，但缺少：

type（hook / reversal / prop / identity / prophecy）
min_distance / max_distance（埋后必须在多少章内回收，否则告警）
paid_off_quality（回收质量 0-5，由质检打分）
volume-level 预算（每卷必须回收 N 个旧伏笔 + 新埋 M 个）
audit 接口（列出超期未收、低质量回收、未被读者感知的伏笔）
编辑视角：网文死于“作者自己忘了的伏笔”。80 个伏笔只回收 30 个，剩下的 50 个变成“读者白等”。必须让系统主动告警，而不是等读者在评论区骂“这个钩子埋了 40 章都没收”。
二、P1 已落地但仍需强化的点
ReaderPromise 尚未反向驱动 draft
表已经建了，也能在 debrief 自动创建，但 draft prompt 里还没有“本章必须/可以兑现的承诺额度”这个高优先级注入。模型不知道“上一章预告‘下一章林凡将面对天劫’，所以第 1-2 场必须是天劫戏”。
方案：draft_assist_stream 增加 active_reader_promises 上下文，prompt 第一段就写：“以下承诺必须在本章处理：…… 允许新建承诺但不得超过 2 个”。同时在 quality_check 中增加“承诺兑现率”维度。

读者模拟器已存在，但未与主流程打通
/reader-simulator 端点已经能让 5 类读者打分，但它目前是独立调用，没有在“写完一章后自动触发”，也没有把“追新型只给 4 分 → 下一章必须加爽点”的结论写进 next_chapter_directives。
方案：GenerationQueuePanel / ChapterEditor 写完后自动跑一次 reader_simulator，把低分项自动转成 directives（例：爽文党 3 分 → 增加 2 个打脸场景）。

质检维度已部分网文化，但仍缺“网文特有硬指标”
读者模拟器帮了大忙，但主 quality_check 仍停留在 plot/character/pacing。缺少：

黄金三章追读引爆度（前 3 章是否让新读者决定留存）
章末钩子星级（1-5 星，5 星 = 重磅反转）
信息密度（每 500 字新信息条数）
爽点节奏频率（打脸/装逼/反转/升级/虐渣）
对话辨识度（盖掉名字能否区分 A 和 B）
套话浓度（黑名单命中率）
POV 漂移检测
方案：把 quality_check 扩到 14 维，每维 1-5 分 + 诊断 + 具体改写建议。T=0.2 的轻量模型完全够用。
三、数据模型层仍需补的“编辑级可检索”能力
关系中间表（outline_node_character、skill_master、faction_member、item_ownership_event）：目前全靠 JSON 扫表，无法瞬间回答“林凡在第 17-47 章出镜密度是不是断崖下降”。
Location 表：地理位置目前是自由文本，角色“17 章在京城、18 章直接在东海”不会被告警。
CharacterMomentum 表：每章每角色出镜字数/关键动作数，用于检测“二号女主已经 12 章没戏份”。
状态机集中化：Chapter.status、OutlineNode.status、Foreshadow.status、MemoryChunk.status、ReaderPromise.status 散落在各处，容易出现非法状态。
四、流程层仍缺的“编辑把关”模式
目前一键生成是“全自动跑到底”。
方案（P2 中期）：增加“编辑工作台”模式：

开局 3 章、每卷转折点、高潮前 3 章，自动暂停。
让“总编辑”先确认章纲 + 分场计划，再继续生成正文。
支持“一键生成 3 套备选分场，挑一套再写正文”。
这既保留了一键的便利，又避免了“全自动跑偏后全盘重来”的巨大浪费。

总结（编辑的狠话）
你现在的一键生成，已经有了“流派指纹 + 语风记忆 + 读者承诺 + 多视角质检”的骨架，但灵魂（节奏、视点、戏份、伏笔预算）仍未真正注入。
三层调度 + 戏份预算 + 伏笔 audit 这三件事做完，AI 味会再降一个大台阶；仪表盘 + 编辑把关模式做完，它才能真正从“能用”变成“专业编辑团队在带作者”。

P0 + P1 已经让你跨过了“能生成像网文的东西”这个坎。
P2 做完，你会跨到“读者愿意追到完本、评论区不骂 AI 味”的下一个坎。
