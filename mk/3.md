### 关键痛点 & 优化建议（从 30 年老作家的视角）

| 痛点 | 影响 | 推荐改进 |
|------|------|----------|
| **章节写作的多次 DB 写入** | 每次 `create / update / delete` 都触发多表清理（MemoryChunk、ChapterIndex、Foreshadow、QualityDebt）导致事务频繁、性能波动 | - 将 **章节重写** 与 **派生数据清理** 合并到单一事务中（使用 `session.begin_nested()`），确保一次性提交。<br>- 引入 **软删除**（`deleted_at`）而非真正删除，避免频繁写入。 |
| **AI 调用串行** | Bootstrap 步骤逐一调用 LLM，累计耗时 30+ 秒，用户等待感受差 | - 对 **无依赖** 步骤（如 `skills`、`items`）采用 **并行 async** 执行（`await asyncio.gather`）。<br>- 对 **必须前置** 步骤（如 `positioning`）做 **缓存**（持久化到 DB），后续调试时可复用。 |
| **缺乏实体关联**（Skill/Item 与 Character） | 业务层只能靠名称匹配，容易出现拼写错误或人物不在列表中，导致后期手动修正 | - 为 `Skill.mastered_by`、`Item.current_owner` 引入 **外键**（`character_id`），在生成阶段先做 **名称→UUID** 映射。<br>- 在 AI Prompt 中加入 `character_names` 列表供模型直接输出 `character_id`。 |
| **字数统计不准** | 中文字符、Markdown、HTML 标签混杂，导致章节字数统计与实际阅读字数不符，影响 Word‑Count 预算 | - 使用 **Tiptap 渲染后的纯文本**（`editor.getText()`）再统计。<br>- 引入 **Unicode 字符宽度** 计算库，区分全角/半角。 |
| **章节顺序漂移** | `normalize_chapter_sort_orders` 只在增删时调用，若批量更新（如导入章节）跳过，前端会出现章节跳层 | - 在 **写入章节**（`create`、`update`）后统一调用 **排序校正**，并在 **批量导入** API 中加入一次性排序。 |
| **质量债务处理硬删** | 删除章节时仅将 `chapter_id` 设为 `null`，但仍保留大量历史记录，查询时需要额外过滤 | - 将 `QualityDebt` 迁移到 **软删除模式**，并在 `list` 接口默认过滤 `resolved` 项。<br>- 为 `QualityDebt` 添加 **关联版本号**，方便追溯。 |
| **一致性检查仅提示** | `_gen_consistency_scan` 只返回需手工确认的列表，缺少 **自动纠正**，影响作者流水线效率 | - 在扫描后自动 **修正** 可预判的错误（如人物名称不匹配、卷章节数不对齐），并在 UI 中标记为 “已自动修复”。 |
| **场景层级缺失** | `Scene` 只生成蓝图，未接入 **章节正文写作** 流程，导致后期章节缺少结构化指导 | - 在 `chapters.update` 时读取 `Scene` 并自动生成 **章节提纲**（章节标题、冲突、目标）作为默认 `payload`，提升 AI 生成的精准度。 |
| **Embedding 服务缺失** | 记忆检索只能基于关键词匹配，语义相似度低，导致情节连贯性差 | - 完成 `embedding_service`：使用 OpenAI/​Ollama `text-embedding-ada-002` 或 `bge-large`，批量生成 `MemoryChunk.embedding`，并在查询时使用 `pgvector` `cosine_distance`。<br>- 为 `Scene`、`Chapter` 增加 `embedding`，实现 **章节级语义检索**。 |
| **缺少并发安全** | 多人协作写章节时，`normalize_chapter_sort_orders`、`clear_chapter_rewrite_derivatives` 可能产生竞争写入 | - 使用 **乐观锁**（`version` 字段）或 **事务隔离级别** 提升并发安全。<br>- 对章节序号改动提供 **锁 API**（如 `POST /chapters/{id}/lock`），防止冲突。 |

### 推荐的短期迭代路线

1. **批量事务化**  
   - 将 `create_chapter`、`update_chapter`、`delete_chapter` 合并成 **单事务**，包括派生数据清理及质量债务处理。  
   - 添加 `soft_delete` 标记，避免硬删导致外键冲突。

2. **并行 AI 步骤**  
   - 在 `_sequential` 中改为 `asyncio.gather` 并行执行 `skills`、`items`、`world_settings`（这些不依赖彼此），仅保留 `positioning`、`project` 的严格顺序。  

3. **外键关联强化**  
   - 为 `Skill.mastered_by`、`Item.current_owner` 引入 `character_id` 外键，修改对应 Prompt 让模型直接输出 UUID。  

4. **字数统计升级**  
   - 引入 `bleach` 或类似库剥离 HTML，使用 `len(text)` + `len(re.findall(r'[a-zA-Z]+', text))` 的综合计数。  

5. **一致性自动修复**  
   - 在 `_gen_consistency_scan` 后添加 `auto_fix_consistency`（如自动补全缺失的卷数、章节数），并在返回 SSE `step_done` 时标记 `auto_fixed=True`。  

6. **Embedding 完成**  
   - 实现 `EmbeddingService.generate_embeddings`，在 `MemoryChunk`、`Scene`、`Chapter` 写入时同步生成向量。  

7. **场景‑章节联动**  
   - 在 `update_chapter` 中读取对应 `Scene`，自动填充 `payload.content` 的章节提纲（`hook`, `conflict`, `goal`），提升 AI 生成正文的指向性。  

8. **并发安全**  
   - 为 `Chapter` 表添加 `version`（INTEGER）字段，使用乐观锁检测更新冲突。  

### 长期愿景（与 30 年写作经验结合）

- **情节连贯度评分**：在章节编辑后自动调用 **质量债务** 检查，并给出 **情节连贯度分数**（0‑10），作者可直观看到章节整体流畅程度。  
- **章节‑场景‑记忆闭环**：实现 **三层调度**：章节 → 场景 → 记忆（向量检索），让 AI 在写章节时自动拉取相关记忆片段，避免信息遗漏。  
- **读者承诺闭环**：`ReaderPromise` 与章节进度实时对比，若章节未兑现承诺自动生成 **提醒**，确保读者钩子不失效。  
- **编辑后置审校**：章节保存后自动触发 **AI 质检**（`quality_debts`），并在 UI 中展示 **可修复建议**，实现“写完即审”。
