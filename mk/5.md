# 设定页（WorldSetting）使用现状与改进方向

> 记录时间：2026-05-23  
> 路由：`/project/{id}/settings` → `SettingsPage` → 表 `world_settings`  
> 相关：Bootstrap Step 8、CLAUDE.md「设定生成架构原则」

---

## 一句话结论

设定页**不是闲置**：写章/质检/连贯性检查会注入设定卡；但用法是「全量或截断 dump」，很多结构化字段（`stage`、`reveal_timing`、地理结构化）**运行时几乎不参与决策**。要从「档案库」升级为「约束引擎」。

---

## 数据是什么

- **WorldSetting 设定卡**：纯叙事约束（世界背景 / 地理场景 / 历史传说 / 文化风俗 / 规则法则 / 其他）
- **不是**「世界观」Tab 的境界/势力/人物/技能/道具（那些有专属表）
- Bootstrap Step 8 按 `GEMINI_SETTING_BLUEPRINTS` 生成约 24 张标准卡
- 前端可 AI：整套重建 / 仅补缺失 / 追加
- 「作品立意」卡保存时会同步 `Project.premise`（仅 `content`）；`extra.core` 与 `Project.extra.positioning` 可能并存两套立意

---

## 当前实际消费路径

| 场景 | 是否用到 | 怎么用 |
|------|----------|--------|
| 章节起草 / 续写 / 重写 | ✅ | `draft_routes` 全项目查卡 → `format_world_setting_context` → `world_summary` → `draft_stream` prompt |
| 章节质检 / gated 质检 | ✅ | 同上 `settings_summary` |
| 连贯性检查 | ✅ | 最多 60 张，带 core/focus |
| 大纲 AI 扩写 / 全量生成 | ⚠️ 弱 | 仅前 4 张，`title + content[:80]` |
| 大纲 QA（story_bible） | ⚠️ 弱 | 前 12 张，仅 `content[:220]`，不用 core/focus |
| 卷扩章纲 | ⚠️ 弱 | 前 6 张，各 80 字 |
| 分场写作（Scene 三层） | ❌ | `scene_draft` 未注入 |
| 复盘 / 记忆提取 / 记忆冲突检测 | ❌ | 不读设定卡 |
| 章纲 linter | ❌ | 不校验世界规则 |
| 语义 RAG（MemoryChunk） | ❌ | 只检索记忆，不检索设定卡 |

### 起草注入逻辑（关键代码）

- `apps/backend/app/routers/ai/draft_routes.py`：`_build_draft_context`
  - **大上下文**：全部卡，`format_world_setting_context`，content 限 2400 字
  - **小上下文**：仅**前 8 张**，每张压到约 120 字
- `apps/backend/app/services/ai/context_builder.py`：`format_world_setting_context` 会输出 `extra.core`、`extra.focus`、`extra.links`（若有）

## 页面上有、下游几乎没用的字段

| 字段 | 设计意图 | 现状 |
|------|----------|------|
| `extra.stage`（early/mid/late/full） | 按进度披露 | 生成时有，**写章不按章号过滤** |
| `extra.reveal_timing` | 何时向读者揭示 | **无任何消费** |
| `extra.who_knows_now` | 开篇谁知道 | **无任何消费** |
| `extra.importance` | core/major/flavor | **无筛选** |
| 地理结构化（location_type、geo_alignment 等） | 写作抓手 | 前端有，**不进 format 与 prompt** |
| `extra.links` | 关联势力/人物 | 格式化时有，Bootstrap 未必填满 |

---

## 和「世界观」Tab 的分工

| 内容 | 存储 |
|------|------|
| 境界、势力、人物、技能、道具 | 专属表 |
| 底层规则、地理、历史谜团、礼法、经济规则 | WorldSetting |

问题：设定卡没有变成**硬规则 enforcement**，和结构化表重复感强，作者改完设定在写作页**无侧栏反馈**。

---

## 应该怎么用（改进 backlog）

### P0 — 最小可行

1. **按章选卡**：用卷 `phase` + 章号过滤 `extra.stage`；未揭示卡（`reveal_timing`）不进起草 prompt
2. **Scene 注入**：分场 `location_name` 命中时注入对应地理卡 + 本章规则卡
3. **立意单一事实源**：`extra.core` ↔ `Project.premise` / `extra.positioning` 同步策略定一处

### P1 — 质量闭环

4. **设定卡 embedding + RAG**：query = 章纲五要素；Top-K 替代全量/前 8 张
5. **章纲 linter 规则 OC-WS**：章纲不得违反 core 规则卡（突破代价、誓约等）
6. **复盘触犯规则** → `QualityDebt` / `consistency_issues`

### P2 — 体验

7. **写作页「本章相关设定」侧栏**（按章纲/分场拉卡）
8. **`extra.links` 与 Faction/Character 表一致性扫描**

## 为何用户容易觉得「没用」

1. 小上下文只带前 8 张，后面十几张等于没参与  
2. 分场、复盘、章纲 linter 不用  
3. 填的结构化字段下游只读一部分 `content`  
4. 与世界观 Tab 重复，但未做成规则校验
