一、完读率盲区 —— 番茄算法的生死线

致命缺失 章纲无完读率目标——番茄的核心 KPI 被忽视

番茄算法逻辑：完读率 > 收藏率 > 评论率。opening_5chapters 为前5章设了完读率目标（60%→50%→45%→40%→40%），但第6章起完读率意识归零。章纲没有 completion_rate_risk 或 drop_risk_point 字段。

番茄作者都知道：第6-15章是算法推荐窗口期，完读率跌破30%就从推荐池出局。系统在这个生死窗口期用的是通用「四元组」模板，跟起点长篇一个规划逻辑。

建议新增字段： completion_rate_risk: "low/medium/high" drop_risk_point: "本章最可能让读者退出的位置（前200字/中段过渡/结尾钩子弱）" → 当 risk=high 时 linter 应阻断或强制要求补充爽点

致命错误 章末钩子不是「文学悬念」，是「广告断点生存术」

番茄读者每读完一章都会看到 5-30秒广告。end_hook 的设计目标不是「让读者觉得故事有趣」，而是「让读者在看完广告后还愿意点击下一章」。这需要极端具体的信息缺口或情绪峰值，不是「主角打开了一扇门」这种通用悬念。

当前 prompt 铁律第4条说「end_hook 必须具体到手法」——方向对了但力度完全不够。番茄的 end_hook 需要分类型设计：悬念型（「来电显示是三年前已经死去的人」）、爽感期待型（「系统提示：下一级奖励已解锁」）、愤怒驱动型（「她冷笑着把离婚协议放到桌上」）。

当前：end_hook 是通用30字描述，无类型分类 建议新增： hook_type: "suspense/satisfaction_preview/anger_driver/revelation/cliffhanger" hook_ad_survival_score: 1-5（过广告存活率预估，≤2 的应 linter 预警）
二、爽感节奏断联 —— 番茄的核心引擎

致命断联 rhythm_map 前50章爽点标签完全没注入章纲

番茄 Bootstrap 花了一整个步骤生成前50章的爽点节奏图：每章标记为 big_win / small_win / progress / transition，并自动检测「连续过渡超2章」的旱区。但章纲展开时完全不读这个数据。

番茄铁律：连续3章没有明显爽感，读者流失率+30%。节奏图已经标出了旱区预警，但章纲 AI 不知道这些预警的存在。

rhythm_map.chapter_tags: [{ch:1, type:"progress"}, {ch:2, type:"small_win"}, {ch:3, type:"big_win"}, ...] → 应注入章纲 prompt：「第X章必须是 big_win 类型，对应打脸对象 Y」 → 并在 linter 中校验：生成的章纲爽感类型是否与 rhythm_map 一致

致命断联 打脸地图与章纲的 has_face_slap 没有对齐

face_slap_map 精确规划了5层打脸对象（从丈母娘到终极 BOSS），每层有具体的 chapter_estimate 和 slap_scene。但章纲只有一个布尔值 has_face_slap: true/false——不知道打谁、用什么方式打、打脸画面是什么。

结果：AI 随机分配 has_face_slap=true，可能第10章就打了第30章该打的人，或者全书打脸对象完全脱离打脸地图的谱系设计。

face_slap_map.targets[0]: {order:1, name:"丈母娘", slap_type:"财富碾压", slap_scene:"当众把支票摔在对方脸上", chapter_estimate:"第3-5章"} 当前：has_face_slap=true（无目标、无类型、无画面） → 应注入：face_slap_target="丈母娘", face_slap_type="财富碾压"

严重断联 金手指升级阶段与章纲 power_milestone 脱钩

golden_finger 设计了5个精确升级阶段，每个阶段有 unlock_ability、visualization（读者脑海画面）、chapter_range。但章纲的 power_milestone 是自由文本，AI 不知道金手指应该在第几章升到第几阶段。

番茄读者追的就是金手指升级→能力展示→打脸这个循环。金手指升级节奏错了，整个爽感链条就断了。

golden_finger.upgrade_stages[1]: {stage:2, name:"小成", unlock_ability:"单手折断对方手腕", chapter_range:"第10-20章"} → 应在第10-20章的章纲中注入：本阶段金手指目标为「小成」 → power_milestone 应强制对齐 golden_finger.upgrade_stages

严重断联 contrast_design 的落差感在章纲中消失

contrast_design 规划了主角的初始状态（最惨的描述）和触发事件时机。但章纲展开时不读这个数据。前10章的每一次「打脸」都应该反复强化主角的初始落差——他越惨，打脸越爽。如果章纲不知道主角「惨在哪里」，就无法设计精准的反差画面。

contrast_design: {initial_state_headline: "被全家唾弃的上门女婿", trigger_event: "老人留下的戒指突然发光"} → 应在前30章章纲中反复注入初始落差作为爽感参照系
三、字数与情绪词错配

严重错误 字数预算偏长——番茄最优区间是 1500-2200 字

当前 expected_words 参考基准：opening 2000-2400，rising 2300，climax 3000-3300。这是起点付费章节的字数标准。番茄免费章节最优区间是 1500-2200 字——更短的章节意味着更高的完读率、更多的广告展示机会、更快的追读节奏。

3000字的高潮章节在番茄上完读率会显著下降——读者的注意力阈值比起点低约 30%。

当前：opening≈2000-2400, rising≈2300, climax≈3000-3300 番茄最优：opening≈1500-1800, rising≈1800-2000, climax≈2200-2500 差距：普遍偏长 300-800 字，高潮章偏长近 1000 字

严重错误 emotional_tone 用的是文学情感词，不是番茄情绪词

当前选项：exciting/tense/sad/romantic/mysterious/funny/epic/calm。这是文学评论的情绪分类。番茄读者的核心情绪只有几种：爽（satisfaction）、燃（hype）、酸（cringe/jealousy）、急（urgency）。

「calm」在番茄上 = 读者退出。「sad」需要极短篇幅后立刻转「爽」。「mysterious」如果不在3段内给出线索就流失。番茄的情绪设计语言和通用网文完全不同。

建议替换为番茄情绪词汇表： shuang — 爽：打脸/升级/碾压后的满足 ran — 燃：热血战斗/逆转/绝地反击 suan — 酸：看反派被打脸时的解气/替代满足 ji — 急：信息缺口/危机悬念/下一章不看不行 nue — 虐：短暂压抑，必须在本章或下章转爽 tian — 甜：感情线糖分，用于调节节奏
四、四元组框架的番茄适配问题

严重错误 「选择暴露性格」是文学批评思维，不是番茄读者心理

四元组「欲望→障碍→选择→代价」是经典叙事理论（Save the Cat / Story Grid 体系），对长篇文学创作确实有效。但番茄读者不关心主角的选择是否暴露性格——他们关心的是：

1. 这章谁被打脸了？（爽点兑现）
2. 金手指有没有新效果？（期待兑现）
3. 下一个要打的人是谁？（期待建立）
4. 反派有没有跳出来？（冲突维持）

四元组可以保留作为底层结构骨架，但番茄章纲需要额外一层「爽感交付清单」：本章交付了什么爽感？类型是什么？强度几级？

建议新增「番茄交付层」字段： satisfaction_delivered: "本章交付的爽感（打脸/升级/揭秘/反转/甜宠，选一）" satisfaction_intensity: 1-5（1=小爽, 5=全书级大爽点） satisfaction_visual: "读者脑海画面（≤20字，必须是动作不是描述）" next_anticipation: "本章建立的下一个期待（读者看完想知道什么）"

中等缺失 番茄没有「过渡章」的概念——每章必须有 payoff

当前系统允许 pacing: slow + emotional_tone: calm 的组合。在番茄上这种章节 = 读者直接弃文。番茄的铁律：每章必须有至少一个 small_win，哪怕是一句让读者解气的台词、一次小小的能力展示、一个让人期待的信息揭示。

rhythm_map 已经用 transition 标签标出了过渡章并自动预警，但章纲 linter 没有「禁止纯过渡章」的规则。

缺失 linter 规则： FANQIE-01: 禁止连续2章 pacing=slow 且无 satisfaction_delivered FANQIE-02: 禁止 emotional_tone=calm 且无 small_win/face_slap FANQIE-03: 每5章必须有至少1个 big_win 级别爽点 FANQIE-04: 前15章（算法窗口期）每章必须有 small_win 以上爽点

中等缺失 缺少「读者爽感记忆衰减」模型

番茄读者对爽感的记忆非常短——上一次大爽点3章之后就「忘了」。如果 big_win 之后连续3章没有至少 small_win 维持，读者会觉得「这书变无聊了」。当前系统没有追踪「距离上次爽感过了几章」的机制。

建议在 linter 中增加： chapters_since_last_satisfaction：追踪爽感间隔 若间隔 ≥ 3 且非 dark_hour 阶段 → 预警 若间隔 ≥ 5 → 阻断（番茄生死线）
五、开局五章与后续章节的断层

致命断联 开局五章精确到200字级别，第6章起退化为30字摘要

opening_5chapters 为每章设计了精确结构：前200字必须完成什么、触发段在第几字、金手指激活段、章末钩子类型。这是番茄级别的精度。

但从第6章起，章纲展开退回到通用的30字 core_event + 30字 opening_hook。从「200字级精度」到「30字摘要」的断崖式降级，直接导致第6-15章（算法窗口期）的写作质量失控。

opening_5chapters.chapter_1.structure: {opening_200_words: "前200字必须完成：建立处境+核心羞辱+读者同情", act_1_setup: "0-400字：主角处境+核心羞辱发生", act_2_trigger: "400-800字：触发事件经过", act_3_finger: "800字-结尾：金手指激活+第一感知"} vol_chapter_plans 第6章起： {opening_hook: "≤30字", core_event: "≤60字"} ← 精度断崖
优先行动路线

P0 · 接通番茄数据管道（1-2天）

在 context_vol_expand.py 中新增 Tier 6「番茄专属层」，从 Project.extra 读取 face_slap_map / golden_finger / rhythm_map / opening_5chapters / contrast_design，组装为 prompt 注入块。确保每章都知道：本章对应哪个打脸对象、金手指处于第几阶段、rhythm_map 标记的爽感类型是什么。

P1 · 番茄化 JSON 输出模板（1天）

新增字段：satisfaction_delivered / satisfaction_intensity / face_slap_target / hook_type / hook_ad_survival_score / completion_rate_risk。调整字数基准到番茄区间（1500-2200）。替换 emotional_tone 为番茄情绪词汇表（爽/燃/酸/急/虐/甜）。

P2 · 番茄 linter 规则集（1天）

新增 FANQIE-01（禁止纯过渡章）、FANQIE-02（爽感密度下限：每5章至少1个 big_win）、FANQIE-03（打脸地图对齐校验）、FANQIE-04（金手指阶段对齐）、FANQIE-05（rhythm_map 一致性）、FANQIE-06（前15章每章必须有 payoff）。

P3 · 番茄专属系统提示词 + 第6-15章强化（半天）

系统提示从「30年网络小说总编辑」替换为「番茄 TOP10 作者 + 运营总监」双角色。核心指令从「因果链」改为「爽感交付链」：每章必须回答「本章读者爽了吗？爽在哪里？看完广告他还会回来吗？」。第6-15章增加200字级结构指引（从 opening_5chapters 的精度标准延伸）。

诊断总结

番茄 Bootstrap 做得很好——它理解番茄的算法逻辑、完读率 KPI、打脸节奏、金手指经济学。但这些精心设计的产物在章纲展开这一步被完全丢弃，退回到了通用网文的文学四元组模式。这不是功能缺失，是数据管道断裂——上游产出了正确的番茄规划数据，下游完全没有读取它们。

修复的核心不是重写章纲逻辑，而是接通管道：让 context_vol_expand.py 读取番茄产物，让 vol_chapter_plans.py 的 prompt 和 JSON 模板感知这些数据，让 linter 按番茄规则校验。P0 阶段的工作量预估 1-2 天，但带来的效果是系统级的——从「番茄 Bootstrap + 通用展开」变成「端到端番茄优化」。
