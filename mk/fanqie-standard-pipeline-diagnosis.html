核心矛盾：一套管线服务两个市场

当前串行步进管线从 system prompt 到 JSON 字段、从字数预算到 linter 规则，全部按起点付费阅读范式设计。番茄是免费+广告模式，算法分发决定流量，完读率决定推荐量。这不是"口味偏好"差异，而是商业模型导致的产品需求根本不同。以下逐模块诊断标准管线在番茄市场下的结构性失配。

1
System Prompt 人设失配

"30年网络小说总编辑" 是起点人设 致命

// vol_chapter_plans.py:161-174 system = ( "你是有30年网络小说从业经验的总编辑，深度参与过数百部上百万字长篇网文的策划。\n" "你的职责：为本卷生成章级大纲，每一章都必须是可以直接开写的创作蓝图，\n" "而不是模糊的情节清单。你知道：\n" " 1. 章节的核心是「主角欲望→障碍→选择→代价」的因果链，不是事件流水账\n" ... )

番茄后果：这个 persona 产出的章纲天然倾向"文学性"——强调内心弧度、认知转变、不可逆变化。番茄读者对"character_change: 谁的认知发生了不可逆变化"的感知极弱，他们要的是「这章谁被打脸了、主角升了什么、下一章谁要倒霉」。

适配方案

当 pace_type == "fast"（已标注"番茄式"）时，system prompt 应切换为番茄向人设：

system_fanqie = ( "你是番茄小说日更百万字作家，深知免费阅读算法的核心指标是完读率。\n" "你的职责：为本卷生成章级大纲，每一章都必须在1800字内完成一个完整的爽感闭环。\n" "你知道：\n" " 1. 章节核心是「爽点触发→爽感释放→下章预期」的三拍循环，不是文学性因果链\n" " 2. 完读率 > 收藏率 > 评论率，章末30字决定读者会不会翻页\n" " 3. 番茄算法窗口期：前30章决定能不能进推荐池，前5章决定能不能过算法初审\n" " 4. 广告插入在章与章之间，每章结尾必须是「不看下章不行」的状态\n" " 5. 反派是打脸素材供应商，不是独立行动线——读者不关心反派在密室里谋划了什么\n" ... )

"四元组叙事引擎" 对番茄过重 严重

protagonist_want → protagonist_obstacle → protagonist_choice → choice_cost 是文学性叙事框架。番茄读者的阅读速度是起点的2-3倍，他们不会注意到"选择暴露了性格"或"代价喂给下一章的债务"。

当前（起点式四元组）

protagonist_want: "证明自己的炼丹实力"
protagonist_obstacle: "内心对失败的恐惧"
protagonist_choice: "选择用险招证明自己"
choice_cost: "险招虽成但丹田受损"

→
番茄式三拍循环

satisfaction_setup: "丈母娘当众嘲讽主角穷"
satisfaction_payoff: "主角当场拍出百万支票"
next_chapter_bait: "丈母娘的闺蜜认出主角是X集团少爷"

适配方案

不废弃四元组（保持系统一致性），但在 pace_type == "fast" 时增加三个番茄专属字段，并在 system prompt 中强调「satisfaction_setup/payoff 是本章核心，四元组是底层结构」：

// 新增字段（pace_type == "fast" 时生效） "satisfaction_setup": "爽点铺垫：谁看不起主角/什么困难摆在面前（≤25字）", "satisfaction_payoff": "爽感释放：主角如何碾压/逆转/震惊全场（≤25字）", "satisfaction_type": "打脸/升级/财富展示/实力碾压/真相揭露/美人倾心", "next_chapter_bait": "下章饵：读者看完本章后最想知道的一件事（≤20字）"
2
字数预算体系：起点标准 vs 番茄最优

字数基线全面偏高 致命

番茄广告插在章与章之间。读者看完一章→广告→决定是否继续。章越短，单位时间内"翻页决策"越多，广告展示越多，算法越倾向推这本书。番茄头部作品章均 1500-2000 字，高潮章最多 2200 字。

卷阶段 phase 当前基线 outline_planning.py:180 番茄实际最优 偏差
opening22001500-1800+22%~+47%
rising23001600-2000+15%~+44%
turning24001800-2000+20%~+33%
dark_hour27001800-2000+35%~+50%
climax30002000-2200+36%~+50%
ending22001600-1800+22%~+38%

番茄后果：章节过长→读者中途退出→完读率下降→算法减少推荐→作品沉底。番茄的 dark_hour 2700 字约等于读者流失率翻倍——免费读者对"慢节奏+长章"的容忍度极低。

适配方案

在 chapter_word_budget_for_phase() 中加入 market_type 参数（从 positioning.pace_type 推导）：

FANQIE_BASE = { "opening": 1600, "rising": 1800, "turning": 1900, "dark_hour": 1900, "climax": 2100, "ending": 1700, } # pacing_mod 也缩小：fast=-100, slow=+100, climax=+200 # 硬上限：2200（番茄高潮章绝对天花板） # 硬下限：1400（太短会被平台判定水章）

同时修改 prompt 尾部的参考字数说明 vol_chapter_plans_prompt.py:125-127。

3
Phase Guidance 节奏约束：缺失算法窗口期概念

Opening 1-5 章：文学开局 vs 算法初审 致命

// phase_guidance.py:28-33 (当前) "【开局1-5章·生死钩子区】前500字必须建立主角核心压力/不公正处境； 主角必须在本章内主动采取行动（不是被动等待）； 每章结尾留下读者必须知道答案的具体问题，不能用「主角沉思」收尾。"

番茄后果：这段约束的关键词是「压力」「主动行动」「具体问题」，全是文学叙事语言。番茄前5章的真实生死线：第1章前200字必须让读者判断出这是什么类型的书（算法靠此匹配读者池），第1章800字前必须触发金手指（否则读者在广告界面流失），前3章必须完成首次打脸（算法完读率基准线）。

适配方案（pace_type=="fast" 时替换）
if ch_num <= 5 and pace_type == "fast": return ( "【番茄开局1-5章·算法初审区】\n" "Ch1前200字：读者必须判断出书的类型（都市逆袭/赘婿/修仙/穿越），不能用悬疑开局；\n" "Ch1前800字：金手指/系统/觉醒必须已触发，读者获得爽感期待；\n" "Ch1-2连续2章都要有可见的小胜利（small_win），证明金手指有用；\n" "Ch3前：首次打脸必须完成（算法完读率基准线），打脸对象要有观众；\n" "Ch4-5：升级第一次打脸的赌注，引入更强的对手或更大的舞台；\n" "每章1500-1800字，结尾必须是『不看下章会后悔』的悬念，禁止反思/回忆结尾。" )

Opening 6-15 章：缺失「算法窗口期」概念 严重

// phase_guidance.py:35-39 (当前) "【开局6-15章·金手指起飞区】主角开始展现核心能力，每3章至少1次具体逆转或胜利； 引入第一条感情线/兄弟情，不能只推主线； 开始埋本卷第一条长线伏笔，制造读者期待。"

番茄后果：6-15章是番茄算法的「推荐定性期」——完读率在这里定型。当前约束"每3章1次逆转"太松，番茄标准是每2章必须有一次爽感释放（小打脸/小升级/小展示都算）。「埋长线伏笔」是起点思维——番茄读者不追伏笔，追的是「下一次打脸什么时候来」。

适配方案
"【番茄6-15章·算法窗口期】\n" "爽感密度铁律：每2章必须有1次可见的爽感释放（打脸/升级/财富展示/实力震惊），\n" "连续2章无爽感=完读率断崖；\n" "金手指升级：至少在第8章和第12章各有一次明显升级（读者需要看到成长曲线）；\n" "打脸升级：打脸对象层级递进（同事→主管→部门经理 或 外门弟子→内门弟子→长老弟子）；\n" "感情线可以开始但不能喧宾夺主——番茄读者来看爽文不是来看恋爱的；\n" "禁止连续2章纯过渡/铺垫，每章必须有一个明确的'本章爽点'。"

dark_hour 阶段对番茄是「毒药」严重

// phase_guidance.py:84-90 (当前) "【至暗期·内心突破区】允许虐主，但每次外部失败必须对应主角内心的认知突破； 节奏放缓，强调情感深度而非事件密度——每章1个情感高点比3个情节事件更重要； 这是人物弧度最深刻的阶段：主角的「最大谎言」（错误信念）必须在本阶段被打破；"

番茄后果：「节奏放缓」「情感深度」「最大谎言被打破」——这三句话足以杀死一本番茄书。番茄读者对虐主的容忍窗口是2章以内，第3章如果主角还没翻盘，读者就走了。「内心认知突破」在番茄是不存在的叙事——读者看不见也不关心。

适配方案
if pace_type == "fast": return ( "【番茄至暗期·快速反弹区】番茄的至暗期≠起点的至暗期！\n" "虐主上限：连续虐主不超过2章，第3章必须开始反弹；\n" "虐法限制：只允许外部困境（被围困/被陷害/资源被夺），禁止内心崩溃/自我怀疑；\n" "暗中蓄力：虐主章内必须埋入翻盘线索（读者能看到但主角还没发现）；\n" "反弹爽度加倍：至暗期后的第一次打脸必须是本书目前为止最大的——\n" "压得越低弹得越高，但压的时间不能超过2章；\n" "字数保持1800-2000，禁止在至暗期膨胀字数写内心戏。" )
4
JSON 输出模板：缺失番茄核心字段

has_face_slap 只是布尔值——无打脸要素 致命

// vol_chapter_plans_prompt.py:120 "has_face_slap": false,

番茄后果：打脸是番茄的核心叙事动力。一个布尔 true/false 完全无法指导写作——谁被打了？打脸类型是什么（武力碾压/财富震惊/身份揭露/知识碾压）？打脸场景有没有观众（有观众的打脸爽感翻倍）？这些信息缺失，写章时 AI 只知道"这章要打脸"却不知道怎么打。

适配方案（pace_type=="fast" 时替换/增强）
// 替换 has_face_slap: bool → 结构化打脸字段 "face_slap": { "has_slap": true, "target": "打脸对象姓名", "slap_type": "武力碾压/财富展示/身份揭露/知识碾压/预言应验", "audience": "在场围观者（有围观爽感翻倍）", "setup_chapter": "铺垫章（哪章埋的钉子）", "escalation": "比上一次打脸升级了什么" } // 无打脸时整个字段填 null

emotional_tone 词表是文学词汇 严重

// vol_chapter_plans_prompt.py:118 "emotional_tone": "exciting/tense/sad/romantic/mysterious/funny/epic/calm"

番茄后果：「mysterious」「calm」「sad」在番茄是无效情绪标记。番茄读者的情绪谱是：爽、更爽、期待、紧张（马上要爽了）、愤怒（替主角愤怒→等着看打脸）。「calm」章在番茄≈读者流失章。

适配方案
// pace_type=="fast" 时使用番茄情绪词表 "reader_emotion_target": "爽快/震惊/期待/愤怒替主角/紧张刺激/温馨（限1章）/得意/解气" // 废弃: mysterious/calm/sad/epic（番茄读者不为这些情绪付费/看广告）

缺失「完读率风险」评估字段 严重

番茄的核心指标是每章完读率。当前 JSON 模板完全没有让 AI 自评"这章可能在哪里流失读者"的机制。

适配方案（pace_type=="fast" 时新增字段）
"completion_risk": "本章最可能导致读者退出的位置和原因（如：中段说明文字过长/无爽点章）", "completion_rate_estimate": "预估完读率（0-100，opening期 ≥55 合格，rising期 ≥45 合格）"

character_change 在番茄是噪音字段 轻微

"character_change": "谁的认知/处境/关系发生了不可逆变化（≤30字，不能只写外部变化）"

番茄后果：「不能只写外部变化」这个约束在番茄是反效果的——番茄读者就是来看外部变化的。内心认知变化对完读率贡献为零。

适配方案

pace_type=="fast" 时，将 character_change 的 prompt 说明改为："power_shift": "本章权力/实力/地位格局变化（谁升了谁降了，≤30字）"

5
Step 0 定位缺失番茄关键维度

positioning 缺少番茄算法关键字段 严重

Step 0 positioning.py 生成的定位产物写入 Project.extra.positioning，包含 face_slap_pattern / pace_type / emotional_arc / target_audience / selling_point / taboo_lines。pace_type="fast" 时已标注"番茄式"，但缺少以下番茄生死字段：

缺失字段为什么致命影响范围
golden_finger_type 番茄书的金手指类型决定整本书的爽感模式（系统流/鉴宝流/医术流），不确定这个就无法生成合理的章纲 opening_5chapters, 全书爽感节奏
golden_finger_trigger 金手指在第几百字触发？番茄标准是800字前，这决定第1章结构 chapter_1 结构
slap_target_hierarchy 打脸对象从低到高的5层级（如：同事→科长→局长→市长→省级）。没有这个层级，打脸会重复同层不升级 全书打脸节奏
satisfaction_density 每N章必须有一次爽感释放的硬约束（番茄标准：每2章一次小爽、每5章一次大爽） rhythm_map, linter
platform_tags 番茄算法靠标签匹配读者池，标签不准=推到错误读者=完读率崩盘 全书定位
适配方案

当 pace_type=="fast" 时，Step 0 的 prompt 中增加上述字段的生成要求。产物写入 Project.extra.positioning 的同级，下游 context_vol_tier12.py 的 _build_positioning_block 读取并注入章纲 prompt。

6
Context Assembly 上下文注入盲区

_build_positioning_block 读取了 pace_type 但没有差异化行为 严重

// context_vol_tier12.py:47 # pace_type="fast" 描述为 "快节奏（番茄式，3-5章一爽点）" # 但仅作为文字描述注入 prompt，没有触发任何结构性差异

pace_type 是一个已经存在的「番茄标识信号」，但整个 context assembly 链从未根据它做分支。它就像一个已经插好但没通电的插头。

适配方案

context_vol_expand.py 在组装 editorial_prompt 时检测 pace_type，当为 "fast" 时：

  • 注入「番茄爽感密度约束块」（每2章一小爽、每5章一大爽、连续过渡不超过1章）
  • 注入「打脸层级递进约束块」（从 positioning 的 slap_target_hierarchy 派生）
  • 注入「金手指升级路线图块」（从 positioning 的 golden_finger_type 派生）
  • 将 character 上下文中的 speech_style 信息纳入（当前 char_snapshot 只含 name/tier/realm/status，遗漏了 speech_style）

char_snapshot 格式过于简陋 轻微

// vol_chapter_plans.py:229-230 char_lines.append(f"{name}({tier},{realm}{status_str})") char_snapshot = "、".join(char_lines)

番茄后果：番茄的角色功能性很强——反派是打脸对象、美女是感情线资源、兄弟是配合打脸的工具人。char_snapshot 不包含角色的「番茄功能定位」（打脸对象/打脸观众/感情线/势力代言人），AI 在分配每章出场角色时缺乏功能意识。

适配方案

pace_type=="fast" 时，char_snapshot 增加 fanqie_role 标签（打脸靶/观众/感情线/辅助）。

7
Linter 规则：番茄生死线零覆盖

无爽感密度规则 致命

当前 linter 规则清单（CH-01~CH-18, SEQ-01~SEQ-07）中，没有任何一条检测爽感间隔。番茄最致命的问题——「连续3章没有打脸/升级/展示」——完全不会被 linter 拦截。

适配方案：新增 FANQIE-* 规则（pace_type=="fast" 时启用）
规则 ID级别检测逻辑
FQ-01blocking 连续≥3章 satisfaction_type==null 且 has_face_slap==false → 爽感断流
FQ-02blocking 前5章内 face_slap.has_slap 全为 false → 首次打脸过晚
FQ-03warning 连续≥2章 pacing=="slow" 或 emotional_tone 含 calm/sad → 节奏拖沓警告
FQ-04warning expected_words > 2200 → 字数超番茄最优区间
FQ-05warning face_slap.target 重复出现≥3次且 escalation 未升级 → 打脸对象卡级
FQ-06blocking opening 阶段 ch1 无 satisfaction_setup → 第1章无爽感铺垫
FQ-07warning completion_rate_estimate < 40 的章节超过卷总章数20% → 完读率系统性风险

SEQ-02 "主线不能连续3章独占" 对番茄过严 严重

// rules_sequence.py: SEQ-02 # 连续 >3 章只挂同一条 storyline → 警告

番茄后果：番茄爽文的核心就是主线推进，连续5章主线打脸升级是常态。强制要求交叉故事线会打断爽感节奏，读者不关心支线。

适配方案

pace_type=="fast" 时，SEQ-02 阈值从 3 放宽到 6；或降级为 info 级别不阻断。

8
编辑铁律：文学标准 vs 算法标准

13条铁律缺失番茄核心约束 严重

当前编辑铁律 vol_chapter_plans_prompt.py:128-149 聚焦于文学性约束（因果链、伏笔回收、反派独立行动线、玄幻禁现代用语等）。番茄核心编辑约束完全缺失：

缺失的番茄铁律为什么是铁律
每章必须有一个明确的「本章爽点」 番茄读者容忍度极低，一章无爽=流失入口
打脸对象必须逐级递升 打同一级别的脸超过3次，读者审美疲劳→弃书
金手指/系统每N章必须展示新功能或升级 金手指是番茄的核心变量，不升级=书不进步
章末最后30字必须制造翻页冲动 广告在章间，最后30字=广告前最后一次说服机会
禁止连续2章纯铺垫/过渡 番茄不是买断制，读者随时可以走
反派铁律修改：反派不需要独立行动线，但必须在每次打脸时提供足够的「反差感」 当前第5条"反派独立行动线是第二引擎"在番茄不成立，反派的唯一功能是给主角当垫脚石
适配方案

pace_type=="fast" 时，在 build_chapter_plan_generation_tail() 中替换/增补铁律条目。保持铁律总数不超过15条（太多AI会忽略）。

9
卷骨架 Step 9 与番茄卷结构不匹配

phase 标记无法表达番茄"黄金30章" 严重

当前 phase 取值：opening / rising / turning / dark_hour / climax / ending。这是经典三幕剧衍生结构，假设读者会完整读完一本书。番茄的现实是：

番茄阶段读者行为当前 phase 是否覆盖
算法初审期（1-5章） 完读率决定能否进推荐池 被 opening 笼统覆盖，无特殊处理
算法窗口期（6-30章） 推荐量爬坡期，爽感密度决定斜率 跨 opening 和 rising 两个 phase，缺统一约束
稳定推荐期（31-100章） 进入推荐池后维持完读率 rising/turning 部分覆盖
长尾期（100+章） 老读者留存+新读者追读 climax/ending 部分覆盖
适配方案

不修改 phase enum（保持系统一致性），而是在 phase_guidance 中根据 pace_type + 绝对章号（在全书中的位置）做二次判定。如：即使某卷 phase=rising，如果该卷的全书起始章号在1-30范围内，仍注入算法窗口期约束。
